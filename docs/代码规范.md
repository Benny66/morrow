# 代码规范

## Go 代码规范

### 命名

| 元素 | 规则 | 示例 |
|---|---|---|
| 包名 | 小写、单数、简短 | `services`、`models` |
| 文件名 | snake_case | `user_service.go` |
| 结构体/接口 | 大驼峰 | `UserService`、`BaseModel` |
| 方法/函数 | 大驼峰（导出）小驼峰（私有） | `GetUserList`、`getUserPermissionCodes` |
| 变量 | 小驼峰 | `pageSize`、`roleIDs` |
| 常量 | 大驼峰或全大写 | `MaxPageSize` |

### JSON Tag

所有模型字段 MUST 带 snake_case 的 JSON tag：

```go
type User struct {
    BaseModel
    Username string `gorm:"uniqueIndex;size:50;not null" json:"username"`
    RealName string `gorm:"size:50" json:"real_name"`
}
```

### 错误处理（管道契约）

- 错误 MUST 显式处理，禁止忽略（`_ =` 需有注释说明）。
- 业务错误 MUST 经 `internal/apperr` 构造，**不得**用 `errors.New` / `fmt.Errorf`
  直接造（否则前端拿不到结构化 `code`——由护栏 `TestBindingsUseAppErr` 强制）：
  - 记录不存在：`apperr.NotFound("xxx不存在")`
  - 入参非法：`apperr.Validation("...")`
  - 状态冲突：`apperr.Conflict("...")`
  - 其他系统错误：`apperr.Wrap(err)`（归一化为 `internal`，原文留在 `Detail`）
- 前端经 `frontend/src/lib/invoke.ts` 的 `invoke()` 归一化为 `{code,message}`，据 `code` 分流。

### 列表与分页（管道契约）

- 列表类绑定方法 MUST 返回 `page.Result[T]`，**不得**返回裸切片。
- 分页参数 MUST 经 `page.Request.Normalized()` 归一化后再查库。
- 页大小上下界（`DefaultPageSize` / `MaxPageSize`）唯一真相在 `internal/page`。

前端侧（镜像，见下方「镜像纪律」）：

- 列表页 MUST 用 `usePagedList`（`src/composables/usePagedList.ts`）承载加载与分页状态，
  不要逐页重写「页码/页大小/总数/loading/error」样板。
- 加载成功后 `page`/`pageSize` MUST 以 Go **回显的归一化值**为准（`usePagedList` 已内建）。
- 前端**不得**自行实现归一化（页码夹取、页大小上下界）——那是 Go 的职责，
  前端发原始值、收归一化值。

### 事件（管道契约）

- 事件名 MUST 为 `<domain>:<action>`（domain 与业务模块名一致）。
- 进度类 payload MUST 含 `done`/`total`；结束类 MUST 含 `ok`。

前端侧（镜像）：

- 事件名 MUST 用 `eventName(domain, action)`（`src/lib/event.ts`）拼装，
  **不得**手写字符串字面量 `'asset:progress'`。
- 组件内订阅 MUST 用 `useEvent`（`src/composables/useEvent.ts`），由组件卸载自动解绑。
  直接 `onEvent` 必须自行调用返回的取消函数——Wails 的订阅会累积，
  漏解绑会让同一事件在路由来回切后触发多次。

> 以上三项即「管道契约」。完整规格见 `openspec/specs/pipeline-contract/`。

## 镜像纪律（管道契约的前端侧）

前端为了编译期可用，对三类 Go 常量各留了一份镜像：

| 单一真相（Go） | 镜像（TS） |
|---|---|
| `internal/apperr` 的 `Code*` | `src/lib/invoke.ts` 的 `ErrorCode` |
| `internal/event` 的 `Action*` | `src/lib/event.ts` 的 `EventAction` |
| `internal/page` 的 `DefaultPageSize` / `MaxPageSize` | `src/lib/page.ts` 的 `PageSize` |

- 改 Go 常量 MUST 同步改镜像，否则 `make test` 的**镜像一致性护栏**
  （`internal/guard/parity_test.go`）会红。
- 镜像**只许复制常量与类型，不许复制逻辑**。一件规则有两个实现比一个常量有两份更糟：
  两者会在边界条件上悄悄分叉。归一化、校验等逻辑仍唯一地活在 Go 侧。
- 命名约定（护栏据此配对，`Go 常量名 = 前缀 + Key + 后缀` ↔ `镜像对象.Key`）不可擅自更改。

## Vue 代码规范

### 命名

| 元素 | 规则 | 示例 |
|---|---|---|
| 组件文件 | PascalCase | `UserList.vue`、`Layout.vue` |
| 页面目录 | kebab-case | `views/system/user/` |
| JS 模块 | camelCase | `request.js`、`format.js` |
| 组合式函数 | useXxx | `useAppStore` |
| 变量 | 小驼峰 | `userList`、`loading` |

### 组件风格

- 使用 `<script setup>` 语法。
- 模板里复杂表达式抽成计算属性或方法。
- 每个页面组件：`<template>` → `<script setup>` → `<style scoped>` 三段式。

### 状态管理目录

MUST 统一使用 `stores/`（Pinia 约定），禁止 `store/` 单复数混用。

## 前端 JS 模块规范

- 工具函数导出用命名导出，一个文件一个职责。
- 调用 Go 后端**直接 import `frontend/wailsjs/go/main/App` 的绑定函数**（Wails 自动生成），
  不经过 HTTP 层；错误处理经 `src/lib/invoke.ts` 的 `invoke()` 包装。
- `src/lib/` 只放**管道**（契约与归一化，无 UI、不依赖 Vue）；
  `src/composables/` 放依赖 Vue 响应式或生命周期的组合式函数（`useXxx`）。
  两者都不放业务规则。

### 前端日志与异常（可观测性）

- 前端日志 MUST 走 `src/lib/log.ts`（`logInfo` / `logWarn` / `logError`），
  **不得**用 `console.*` 作为正式出口——打包后无 DevTools，console 是无人可见的输出。
  该模块经 Wails runtime 送到 Go，最终落进 `app.log`。
- 全局错误兜底 MUST 在 `main.ts` 挂载前安装（`installGlobalErrorHandler` +
  `app.config.errorHandler = createVueErrorHandler()`），否则启动期异常捕获不到。
- 异常如何【呈现】给用户（toast/弹窗）属产品面，由下游经
  `installGlobalErrorHandler(hook)` 接管；基座只保证不丢。

> 这条链路的 Go 侧接线（`options.App.Logger`）由
> `internal/guard/wiring_test.go` 强制——漏接不会有任何症状，只会静默丢日志。

## 命令与验证

- `make lint` = gofmt + Go 护栏 + `go vet` + ESLint + **`vue-tsc` 类型检查**。
  类型检查不可省：开发态 `vite` 只剥离类型不做检查，缺了这步类型错误会一路漂到打包才炸。
- 未使用变量由 `vue-tsc` 兜（tsconfig 的 `noUnusedLocals` / `noUnusedParameters`），
  ESLint 的基础 `no-unused-vars` 已对 TS 关闭（它会把类型注解里的函数类型参数误报为未使用）。

## 通用规范

- 注释使用中文（项目编码语言为中文）。
- 提交前移除 `console.log`、调试代码。
- 不提交数据库文件、构建产物、依赖目录（见 `.gitignore`）。
