# 智能免打扰只使用本机活跃度，不使用摄像头或屏幕内容

Morrow 的智能免打扰（自动暂停）只依据本机活跃度信号做判断：系统空闲时长、锁屏/休眠状态、前台应用身份（会议软件）以及全屏状态。不使用摄像头、不采集屏幕内容、不读取键鼠输入内容，也不把这些信号上传。

## 补充：全屏识别允许申请屏幕录制权限，但只读窗口几何

全屏识别在 macOS 上需要读取前台窗口的几何信息。若实测必须通过屏幕录制权限才能获得该信息，允许向用户申请，但严格限定为：

- 只读取窗口边界、所属应用与窗口层级，用于判断「前台窗口是否铺满当前屏幕」。
- 不读取窗口标题、不截图、不录屏、不分析像素内容、不落盘、不上传。
- 权限说明必须写清「仅用于判断全屏，不采集屏幕内容」；用户拒绝后立即降级为空闲检测 + 会议应用前台识别，不反复弹窗。

## 备选方案

- **摄像头在场/眨眼检测（LookAway 路线）**：判断「人在不在电脑前」更准，但需要摄像头权限，直接削弱 Morrow「本地优先、无感」的定位；macOS 权限与信任成本高，且会把休息提醒变成监控感更强的产品。
- **只做手动暂停 + 静默时段**：零隐私风险、实现最简单，但解决不了「开会时被弹窗打扰」这一核心痛点，基础能力仍是缺的。
- **仅接入系统专注模式/日历忙闲**：能覆盖会议与专注，但依赖系统权限与平台适配，且无法感知「离开了电脑」。

## 后果

- 产品不能声称能判断「人在电脑前但没看屏幕」；相关文案只描述可观测的活跃度、前台应用与窗口几何。
- 会议/全屏识别依赖一份本地应用名单与平台能力，名单需要维护；macOS 与 Windows 的识别精度允许不同，但都必须遵守「不采集内容」。
- 屏幕录制权限只服务于全屏几何判定；若后续要截屏分析或引入摄像头，必须新开 ADR 重新评估隐私承诺与用户授权。
