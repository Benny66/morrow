# 应用使用画像只存本机、全量长期保留，并由用户显式同意

为了让宠物知道「你最近在做什么、坐了多久」，Morrow 记录前台应用的标识、起止时间、连续时长与行为类别，全量明细保留至用户手动删除。数据只存在本机，不上传、不进入遥测；不记录窗口标题、屏幕内容、键鼠输入内容，也不使用摄像头。首次引导必须显式同意；拒绝则降级为基础久坐检测（只算连续用机时长，不读应用身份）。

## 边界

- 应用名只在用户主动打开的「久坐」页可见；宠物气泡只使用行为类别，不直接点名应用。
- 行为类别由内置名单映射，未知应用归「其他」，用户可在久坐页纠正；纠正只存本机。
- 宠物记忆使用类别级会话与派生规律，不逐条回放原始应用流水。
- 关闭画像时立即停止记录，并让用户选择保留或删除历史；删除历史只删应用会话、类别与记忆，不追溯改写已计入目标的打卡记录。
- 导出数据库时询问是否包含应用画像；取消后导出的库不含相关表。
- 用户拒绝或关闭画像后，久坐功能退化为基础久坐检测，不反复询问授权。

## 备选方案

- **只存当前会话**：隐私风险最低，但没有跨天记忆，无法做「你最近下午容易连坐」这类判断。
- **按日聚合、保留 30 天**：适合趋势，但判断不了连续久坐，也丢失应用切换上下文。
- **用 AI 自动分类应用**：会把应用名发送给模型，破坏本地优先与不上传承诺。
- **不做应用画像**：只能得到时间结论，宠物的上下文与深度记忆无从谈起。

## 后果

- 本地数据库会包含敏感的工作习惯信息，泄露面比只存聚合统计更大；必须提供可查看、可纠正、可清空、可关闭的完整控制面。
- 数据长期保留会让库持续增长；需要按会话而不是按轮询采样落库，并做定期整理。
- 该决策扩展了 ADR 0004 的数据面（前台应用身份从「会议识别」扩展到「使用画像」），但未改变「不读内容、不上传、不用摄像头」的底线。
