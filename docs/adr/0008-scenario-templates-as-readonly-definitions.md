# 场景模板是只读定义，选用即复制成普通场景

场景模板以 Go 内置的只读定义存在（名称、描述、整套确定性提醒项），不落库为内置场景行、也不给场景加 `is_builtin` 标记。用户选用时复制成一个普通场景及其提醒项副本，之后与自建场景完全同权，可编辑、可启用、可删除；模板内容随应用版本更新，已有副本不回溯。模板不调用 AI，不需要 API Key，离线可用。

## 备选方案

- **首次启动预置成真实场景行**：实现直白，但场景列表会混入非本人创建的内容，删除后是否自动回来语义模糊。
- **带 `is_builtin` 标记的真实场景**：升级时可刷新模板内容，但需要改表，并让删除、编辑、重置各有一套特殊语义，维护成本最高。
- **模板也交给 AI 生成**：内容更灵活，但与「无 Key 也能在 2 分钟内拿到计划」的目标直接冲突，也无法离线与审校。

## 后果

- 模板更新只影响此后新建的副本；用户对副本的编辑永不丢失，「重置」等于删除副本后重新选用。
- 不需要数据库迁移；模板内容作为代码的一部分参与版本管理与测试。
- 场景页与首次引导都只是模板定义的消费者，模板清单只有 Go 侧一个出处。
