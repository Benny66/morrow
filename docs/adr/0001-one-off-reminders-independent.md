# 一次性提醒独立于场景，并复用 reminders 表

一次性提醒是用户明确指定的「绝对日期 + 时刻」事件，不是场景习惯的一部分；场景停用不应让它静默消失。因此 `reminders` 表新增 `once_at`（绝对 Unix 时间，0 表示周期项），一次性项的 `scenario_id` 置空，调度引擎按 `once_at` 全局扫描，不受场景启停影响。选择复用现有触发记录、待处理与推迟机制，而不是新建独立表，是因为独立的触发状态机会把完成/跳过/推迟/去重变成两套实现，迟早漂移。

## 备选方案

- **归属场景并随场景静音**：实现最省事，但停用场景后一次性提醒会无声不响，且无场景时无法创建。
- **独立主表 + 独立触发状态机**：概念最纯，但触发状态机、待处理查询与推迟队列都要写两份。

## 后果

- `reminders.scenario_id` 需允许为空；待处理查询与场景 JOIN 要改为 LEFT JOIN。
- 今日目标、连续天数、宠物生长只统计场景内周期项，一次性项不参与。
- 引擎新增一条「全局一次性到期扫描」，与现有「当前启用场景网格」并列。
