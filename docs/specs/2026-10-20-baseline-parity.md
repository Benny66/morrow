# 基础能力补齐：智能免打扰 + 场景化休息模式 + 桌面集成

> 前置共识：[`docs/competitive-analysis.md`](../competitive-analysis.md)
> 术语：[`CONTEXT.md`](../../CONTEXT.md) 中的「泛办公健康 / 基础能力 / 差异化能力 / 智能免打扰 / 顺延不补发 / 休息模式 / 引导动作」
> 决策：[`docs/adr/0003`](../adr/0003-general-office-wellness.md)、[`0004`](../adr/0004-smart-pause-local-signals-only.md)、[`0005`](../adr/0005-p1-busy-free-only.md)

## 问题陈述

Morrow 当前的提醒形态停留在「定时弹窗 + 跳过/推迟」。2026 年的桌面健康提醒工具（Stretchly、LookAway、Shui、CareDesk 等）已经把「空闲/会议自动暂停、休息引导、菜单栏入口、多屏覆盖」做成了共同下限。Morrow 缺这些能力，导致两个问题：

1. **提醒疲劳**：开会、离开、看视频时仍然被弹窗打扰，用户两周后倾向关掉通知或直接卸载。
2. **休息质量**：全屏强提醒只解决了「看见」，没解决「接下来做什么」；喝水、起身、护眼三类提醒在体感上没有区分。

补齐基础能力的同时，必须保留 Morrow 的差异化组合：自然语言场景 → 整套计划、桌面宠物承载进度、本地优先无账号。不能为了追平竞品而引入摄像头监控、严格模式或云端统计。

## 方案概述

分两期交付，全部长在宠物/场景载体上：

- **P0**：智能免打扰（空闲/锁屏/会议/全屏）+ 场景化休息模式（stand/move/rest 三类）+ 菜单栏快捷入口 + 多屏强提醒。
- **P1**：系统专注联动 + 日历忙闲感知；只读布尔状态，默认关闭、显式授权。

不新建云端、不引入摄像头、不做严格模式、不做历史趋势。

## 用户故事

### 智能免打扰

- **US-1**：当系统连续 5 分钟无键鼠输入时，应用进入「空闲暂停」状态；期间到点的提醒不投递、不生成待处理。
- **US-2**：当系统锁屏或休眠时，应用立即进入暂停状态；唤醒/解锁后恢复调度。
- **US-3**：当 Zoom / Teams / Webex / 腾讯会议 / 飞书 / 钉钉 / FaceTime 任一应用处于前台时，应用进入「会议暂停」状态；不读取会议内容。
- **US-4**：当 macOS 前台窗口铺满当前屏幕（按窗口几何判定）时，应用进入「全屏暂停」状态；Windows 同理。
- **US-5**：暂停期间到点的周期性提醒**顺延不补发**——恢复后按原间隔重新计时，不投递、不进待处理。
- **US-6**：暂停期间错过的每日单点或一次性提醒，在首页保留「已错过」可见条目，不补弹。
- **US-7**：设置页提供四项触发条件的独立开关（空闲/锁屏/会议/全屏），默认全部开启；关闭后对应触发不再生效。
- **US-8**：若 macOS 全屏识别必须申请屏幕录制权限，首次启用时向用户申请，说明「仅用于判断全屏，不采集屏幕内容」；用户拒绝后降级为空闲 + 会议识别，不反复弹窗。

### 场景化休息模式

- **US-9**：stand / move / rest 三类提醒到点前 60 秒，宠物气泡与菜单栏同步显示预警文案；不发系统通知。
- **US-10**：到点时进入休息模式：覆盖层显示倒计时与一条与类型匹配的内置引导动作（rest → 远眺/呼吸，stand → 肩颈拉伸，move → 走动），宠物同步进入「陪做」状态。
- **US-11**：倒计时结束时，应用自动记一条「完成」CheckIn，并退出休息模式。
- **US-12**：用户在倒计时中点击「提前结束」时，弹出「算完成 / 跳过」二选一；分别写入对应 CheckIn 动作。
- **US-13**：water / toilet / custom 三类提醒不进入休息模式，保持现有的简单打卡流程。
- **US-14**：休息模式的引导动作由内置内容包提供，不调用 AI；每种类型至少 1 个动作，离线可用。

### 菜单栏快捷入口

- **US-15**：macOS 菜单栏与 Windows 托盘菜单显示今日完成/目标、下一条提醒时间、待处理数量。
- **US-16**：菜单提供「打开主窗」「查看待处理」「退出」三项操作。
- **US-17**：当应用处于智能免打扰状态时，菜单栏图标与菜单项同步显示暂停原因（空闲/会议/全屏）。

### 多屏强提醒

- **US-18**：强提醒窗口覆盖所有显示器，每个屏幕都可独立处理提醒。
- **US-19**：主屏行为不回归——主屏仍优先显示待处理卡片与操作入口。

### P1：系统专注联动

- **US-20**：macOS 上通过公开的 Focus 状态接口读取系统专注是否开启；开启时自动暂停提醒，关闭后恢复。
- **US-21**：Windows 上若存在等价公开能力则实现；若不存在，P1 不降级也不报错。

### P1：日历忙闲感知

- **US-22**：macOS 上通过系统日历权限读取「当前是否忙」的布尔状态；忙碌时暂停，空闲后恢复。
- **US-23**：不读取事件标题、参与人、备注、地点；不进入 AI 提示词；不落盘。

### P1：授权与降级

- **US-24**：专注与日历默认关闭；首次开启时弹出授权说明，明确「只读忙闲，不读内容」。
- **US-25**：用户拒绝授权后，静默降级为空闲/会议/全屏识别；不弹二次请求。
- **US-28**：三个敏感权限（屏幕录制 / 专注 / 日历）未授予时，设置页提供「去系统设置」按钮：
  - 从未申请过 → 先走一次说明窗与系统弹窗（让应用出现在隐私列表里）；
  - 已拒绝 → 直达对应的「隐私与安全」面板；
  - 深链打不开时给出手动路径文案，按钮不能点了没反应；
  - 授权后回到应用即刷新为「已授权」，屏幕录制额外提示可能需要重启。

### 宠物状态表达

- **US-26**：宠物气泡在暂停期间显示「我先不打扰」+ 暂停原因；恢复后回到正常状态。
- **US-27**：休息模式中宠物进入「陪做」状态，与引导动作同步。

## 测试决策

### 接缝

- **`internal/reminder/engine.go`**：调度循环；在此接入「暂停信号」门控，决定 fire 是否投递。
- **`internal/pause/`（新）**：暂停信号提供者，输出 `PauseReason`（idle / lock / meeting / fullscreen / focus / calendar）；各触发独立实现，可单元测试。
- **`internal/restmode/`（新）**：休息模式编排（预警 → 倒计时 → 引导 → 完成/跳过）；纯状态机，可单元测试。
- **`internal/service/checkin.go`**：CheckIn 记录；休息模式完成/跳过复用既有动作常量。
- **`app.go`**：绑定方法暴露给前端（`GetPauseState`、`EnterRestMode`、`ExitRestMode` 等）。
- **`internal/tray/tray.go`**：菜单栏菜单动态更新。
- **`frontend/src/views/Pet.vue`**：宠物状态映射（正常 / 暂停 / 预警 / 陪做）。
- **`frontend/src/views/Alert.vue`**：休息模式覆盖层与倒计时。
- **`frontend/src/views/Settings.vue`**：四项触发开关、P1 授权入口。

### 验收

- **P0**：`make test` 与 `make lint` 通过；macOS 上手动验收 8 个场景（会议中不投递、离开后恢复、全屏识别、休息模式完成/跳过、菜单栏状态、多屏强提醒、宠物状态、设置开关）。
- **P1**：macOS 上验收专注与日历的授权流程、忙闲切换、拒绝降级；Windows 上验收「无等价能力时不报错」。
- **两周自用**：本地日志与 CheckIn 数据满足——暂停期间零投递；休息模式完成率与基线持平或上升；跳过/推迟率不显著上升；宠物与菜单栏的暂停状态无需解释即可理解。不设拍脑袋阈值。

### 护栏

- `internal/guard/` 新增护栏：暂停信号提供者必须实现 `PauseReason` 接口；休息模式状态机必须覆盖「未开始 / 预警 / 倒计时 / 完成 / 跳过」五种状态。
- `internal/guard/parity_test.go` 新增：`PauseReason` 枚举与前端镜像一致。

## 明确不做

- **手动暂停 15/30/60 分钟**：先靠自动触发与逐项开关；两周自用观察误判率后再评估。
- **摄像头在场/眨眼检测**：与本地优先定位冲突（ADR 0004）。
- **严格模式/强制不可跳过**：与陪伴、温和的定位冲突。
- **历史趋势与周报**：CheckIn 已具备数据基础，本轮优先补交互闭环。
- **AI 生成休息内容**：休息引导使用内置确定性内容，离线、可审校、不产生医疗建议。
- **日历事件标题、屏幕内容分析、云端同步**：隐私边界之外。
- **Linux 平台**：CI 未覆盖，本轮不纳入。
- **休息时长/预警时间可配置**：首版固定默认值（rest 60s / stand 120s / move 180s / 预警 60s），后续再评估。

## 补充说明

### 默认参数

| 项 | 默认值 | 说明 |
|---|---|---|
| 空闲判定 | 连续 5 分钟无键鼠输入 | 设置项可改 3/5/10 分钟；锁屏/休眠立即暂停 |
| 会议应用 | Zoom、Teams、Webex、腾讯会议、飞书、钉钉、FaceTime | 按前台应用身份识别；不读会议内容；浏览器内会议靠全屏兜底 |
| 全屏判定 | 前台窗口铺满当前显示器工作区 | macOS 若必须申请屏幕录制权限，只读窗口几何；拒绝则降级 |
| 提前预警 | 60 秒 | 宠物气泡 + 菜单栏，不发系统通知 |
| 休息时长 | rest 60 秒；stand 120 秒；move 180 秒 | 首版固定，后续再评估是否可配置 |
| 恢复策略 | 恢复后按原间隔重新计时 | 不补发、不积压 |
| P1 授权 | 专注/日历默认关闭 | 首次开启时说明「只读忙闲，不读内容」 |

### 平台差异

- **macOS**：完整实现所有 P0 + P1 能力。
- **Windows**：P0 先保证空闲、会议应用、托盘与多屏提醒可用；全屏识别按 Windows API 实现（无权限成本）。P1 专注/日历若 Windows 无等价公开能力，保持 P0 行为，不报错。
- **Linux**：本轮不纳入。

### 风险

1. **全屏识别权限**：macOS 上读窗口几何是否必须屏幕录制权限需实测；若必须，按 ADR 0004 的补充条款只读几何、不截屏，并在拒绝时降级。
2. **浏览器内会议**：前台应用识别不到 Google Meet / 飞书网页版；全屏信号可覆盖一部分，但无法保证 100%。产品文案不能承诺「所有会议都能识别」。
3. **宠物状态过载**：暂停、预警、休息、待处理、庆祝都挂在宠物上，需限制状态优先级与文案长度，避免宠物变成仪表盘。
4. **休息内容维护**：内置动作先做最小集（每类 1–2 个），后续扩充需内容审校，不能让 AI 现场生成医疗建议。
5. **休息模式与强提醒冲突**：若用户已在休息模式中，下一轮提醒不应再触发强提醒；需明确状态优先级。
