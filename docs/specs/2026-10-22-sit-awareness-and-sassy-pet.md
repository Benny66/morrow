# 久坐感知与毒舌宠物 — 规格说明书

- 日期：2026-10-22
- 来源：`grill-with-docs` 共识（2026-10-22）、`CONTEXT.md`、ADR 0009 / 0010 / 0011
- 状态：ready-for-tickets（供 `to-tickets` 切分垂直切片）
- 目标用户：中文办公人群（见 `CONTEXT.md`）
- 范围：久坐感知、应用使用画像、与现有定时提醒结合、宠物情绪与记忆、默认毒舌人格、新增「久坐」页
- 范围外：见第 6 节

## 1. 问题陈述

**宠物目前只在提醒到点时说话，不知道用户已经连续坐了多久。**

- 现有智能免打扰只读取系统空闲时长，且只用于「暂停提醒」；没有累计连续用机时长的时钟。
- 固定排程无法接住两种真实情况：用户已经坐得太久、而离下一条站立/走动提醒还很远；用户刚真正休息过、下一条提醒马上就要弹。
- 宠物没有「观察到你在做什么」的上下文，只能复述提醒标题；「拟人化」停留在动画与文案层。

**用户想要一个会观察、会记得、会开口的宠物。**

- 需要知道用户是否长时间在用电脑，并在合适时机提醒，而不是再加一个固定计时器。
- 需要与现有定时提醒共存：正式提醒仍是用户计划，久坐感知只做加减法。
- 需要清楚知道数据被记了什么、为什么记、怎么关、怎么删。

**这件事值得做，因为时机与坚持是当前产品的两个缺口。**

- 竞品证据（`docs/competitive-analysis-round2.md` P2 / P4 / P5）显示：用户最烦「在不合适的时机被打断」与「提醒变成噪音」；固定排程解决不了。
- 桌宠是 Morrow 的差异化载体；让它感知久坐，比再加一个通知通道更符合「提醒的化身」定位。
- 默认毒舌人格是明确的产品转向（ADR 0011），需要一次性把数据边界、表达边界与安全底线写清。

**诚实边界：** 本功能测量的是「连续用机」，不是「真实坐姿」。没有摄像头、没有可穿戴设备，产品文案不得声称能判断用户是否物理上坐着；「久坐」是功能名，数据口径是「连续用电脑」。

## 2. 方案概述

### 2.1 总体形状

- 新增 `internal/sit` 深模块，四块纯逻辑：
  - `Tracker`：久坐时钟与状态机。输入当前时间、系统空闲时长、锁屏状态、前台应用、场景/提醒快照与用户动作；输出 `Snapshot`。
  - `Policy`：软提醒阈值、间隔、空档判断、主动发言预算、休息跳过窗口、目标抵扣选择。
  - `Memory`：从持久化的类别级会话与休息事件派生规律，选择记忆模板。
  - `Category` / `Template`：应用 → 行为类别的内置映射与三档语气文案。
- 运行时在组合根新增 `sit_runtime.go`，启动一个 5 秒采样器；只在「有启用场景 + 场景内至少一条 stand/move 提醒 + 当前处于这些提醒的生效时段」时工作。它复用 `pause` 已有的空闲、锁屏与前台应用读取能力，不新增系统权限。
- 持久化仍在主 SQLite 库：新增 `app_usage_sessions`、`sit_sessions`、`sit_breaks`、`sit_speeches`、`app_category_overrides`；`check_ins` 增加 `source` 列。所有模型登记进 `model.AllModels()`。
- 与提醒引擎只加一个窄接口 `reminder.BreakProvider`：引擎在占用 stand/move 触发点前问一句「刚休息过吗」，是则把该触发点落成 `FireSilent`，不投递、不算错过。其余调度逻辑不变。
- 久坐软提醒不经过提醒引擎：不发系统通知、不弹全屏、不进待处理、不写 CheckIn。宠物窗口通过 `GetSitSnapshot` 轮询，真正渲染气泡时调用 `AckSitBubble` 确认展示；预算按已确认展示的气泡计数。
- 前端：`Pet.vue` 复用 4 秒轮询，新增情绪层与最低优先级气泡；新增 `/sit` 页面；`Settings.vue` 增加久坐区域；`Welcome.vue` 增加应用画像同意页；已完成的升级用户看到一次性同意卡。
- 不新增事件域。主动休息与锁屏记账写入 `CheckIn` 后广播既有 `reminder:changed`；久坐状态只走绑定轮询。

### 2.2 接缝（deep module）

优先在高接缝测试，不直接测 Wails 窗口。

1. **`sit.Tracker`（纯状态机）**：`Observe(Input) Snapshot`。测试主靶心；不碰数据库、不碰平台 API。
2. **`sit.Policy`（纯函数）**：`NudgeDecision`、`ShouldSkipStandMove`、`CreditDecision`、`BudgetDecision`。测试主靶心。
3. **`sit.Memory`（纯函数）**：`Facts` + `SelectQuote`。测试主靶心；不调用 AI。
4. **`service`（真实 SQLite）**：新模型、CheckIn source、抵扣事务、清空/导出；用现有临时库测试模式，不用 mock SQL。
5. **`reminder.BreakProvider`（窄接口）**：`ShouldSkipStandMove(reminderID uint, fireAt int64, now time.Time) bool`。引擎在占用最新到点触发点前调用；测试注入 fake。
6. **`App` 绑定**：`GetSitSnapshot` / 动作 / 页面查询；契约由 `frontend/src/lib/sit.ts` 镜像与 `internal/guard/parity_test.go` 双向校验。
7. **复用现有接缝**：`pause.GetIdleDuration` / `IsIdleSupported` / `GetFrontmostApp` / `LockDetector`、`reminder.NextFireAt` / `InQuietHours`、`model.DateLayout`、`config` 的设置读写、`service` 的 `CheckIn` 事务、`reminder:changed` 事件。

### 2.3 状态与优先级

- 久坐状态：`idle` / `tracking` / `break_wait` / `muted` / `unsupported`。
- 宠物情绪：`energetic` / `concerned` / `droopy`；是表现层，不参与计时。
- 气泡优先级（在现有链上追加，最低）：
  **陪做 > 预警 > 顺延 > 演示建议 > 暂停 > 待处理 > 久坐软提醒 / 记忆气泡**
- 正式提醒永远压过宠物主动发言；有待处理提醒、休息倒计时、暂停、专注会话或用户正在输入时，久坐气泡不出现。

## 3. 用户故事

### A. 同意、设置与启用

**A-1 首次引导新增应用画像同意页**
干净安装完成现有三步引导后，增加一页「久坐感知」：说明会记录前台应用名、起止时间、时长与行为类别，只存本机、不上传，不读窗口标题、屏幕内容或键鼠输入；同时告知小满默认说话比较直（毒舌），可在设置里切换。用户必须选择「开启应用画像」或「只使用基础检测」；两者都不阻塞完成引导。
验收：完成引导后 `OnboardingCompleted=true`；选择开启时 `SitProfileEnabled=true`、`SitProfileAsked=true`；选择基础时 `SitProfileEnabled=false`、`SitProfileAsked=true`；跳过整段引导时不设置 `ProfileAsked`，首页出现一次性同意卡。

**A-2 拒绝应用画像的降级**
拒绝后仍运行基础久坐检测：全局久坐时钟、分级空闲、时间驱动的软提醒与三态情绪；不读取前台应用身份，不做行为类别、专注会话与深度记忆。
验收：拒绝后数据库没有新的应用会话；宠物仍能在连续用机超阈值时冒泡，但只说「坐了多久」，不提类别；设置页显示「仅基础检测」。

**A-3 升级用户的一次性同意卡**
已有场景、已完成引导的升级用户，首次启动新版本时在首页看到一张说明卡，含「开启应用画像」「只使用基础检测」两个动作，并告知默认人格为毒舌、可随时在设置或气泡里切换；选择后不再出现，设置里仍可改。卡片不阻塞其他功能。
验收：升级用户不进入完整引导；卡片选择后 `ProfileAsked=true`；重启不再出现；基础检测在卡片选择前是否工作不影响已有提醒。

**A-4 设置区域**
设置页新增「久坐感知」区域：
- 总开关（默认开）；
- 应用画像开关（默认关，首次开启必须经过同意说明；关闭时询问「保留历史 / 同时删除」）；
- 久坐提醒阈值：45 / 60 / 90 分钟，默认 60；
- 语气：毒舌 / 活泼 / 温和，默认毒舌；
- 平台能力只读状态：支持 / 不支持 / 权限或读取异常；
- 数据控制：查看久坐记录、清空应用与久坐数据；
- 一段隐私说明与「软提醒依赖桌面宠物」的提示。

验收：设置往返后重新读取值与保存值一致；非法阈值夹到最近档；非法语气回落毒舌；关闭画像立即停止采样；选择删除时清空应用与久坐数据。

**A-5 总开关与当天静音**
总开关关闭后，不采样、不冒泡、不改情绪；正式提醒不受影响。「今天先这样」只静音当天，次日自动恢复。
验收：关闭总开关后重开应用仍保持关闭；「今天先这样」重启后仍静音当天，跨日后恢复；正式提醒在整个过程中照常。

**A-6 平台降级**
macOS / Windows 支持；其他平台或空闲读取不可用时，久坐感知整体禁用，设置页与久坐页显示「当前平台不支持久坐感知」，不静默失败。正式提醒保持原行为。
验收：在不可用平台上不产生久坐数据、不冒泡；设置页有明确文案；没有反复报错或空转采样。

**A-7 默认值与夹取**
阈值为 45/60/90，默认 60；语气为 sassy/lively/gentle，默认 sassy；`SitEnabled` 默认 true；`SitProfileEnabled` 默认 false，直到用户同意。配置是用户可写文件，非法值必须夹取或回落，不得让采样器崩溃。
验收：手改阈值 47 → 回显 45；手改语气 `"x"` → 毒舌；缺省字段继承默认值。

### B. 久坐时钟与休息

**B-1 全局时钟**
只维护一个久坐时钟：有键鼠输入即累计；切换应用不重置；应用切换不产生新的计时起点。
验收：连续使用 IDE → 浏览器 → IM 30 分钟，久坐时长连续；单独看某个应用不会得到「它自己坐了多久」的健康计时。

**B-2 分级空闲**
无输入 0–5 分钟继续计时；5–15 分钟暂停计时但不清零；≥15 分钟视为真实休息并清零。分级阈值固定，不跟随「智能免打扰」的空闲阈值设置变化。
验收：读资料 8 分钟不清零、不继续累计；离开 16 分钟清零；把暂停空闲阈值改为 10 分钟不影响这三段语义。

**B-3 锁屏与休眠**
锁屏/休眠视为真实休息：清零久坐时钟；锁屏时长用于「锁屏自动记账」判定；休眠与锁屏不可区分时，按可观测的空闲/锁屏信号处理。
验收：锁屏 1 分钟只清零不记账；锁屏 6 分钟且本次已坐 31 分钟自动记一次目标完成；解锁后从 0 开始。

**B-4 专注会话**
应用画像开启时，同一应用连续使用 ≥10 分钟视为专注会话；短暂切走不超过 120 秒不打断，切走超过 120 秒或进入其他类别则结束。专注会话只影响宠物开口时机，不驱动久坐时钟，也不改变正式提醒。
验收：写代码 40 分钟不出现软提醒；切到浏览器查资料 30 秒再切回，专注会话继续；切到另一应用 3 分钟后，原专注会话结束。

**B-5 主动休息**
用户点「起来走走」后立即清零久坐时钟，进入 `break_wait`；宠物说「去吧，我等你」。检测到输入恢复后，记录休息时长（从点击到首次输入，至少 0 秒），宠物打招呼并回到 `tracking`。不设倒计时，不阻断用户。
验收：点击后久坐时长归零；离开 3 分钟回来，记录约 3 分钟休息并显示欢迎回来；离开不足 30 秒也按用户自报记为休息，不做惩罚。

**B-6 锁屏自动记账**
锁屏持续 ≥5 分钟且锁屏开始时本次久坐 ≥30 分钟，解锁时自动抵扣一次最近到点的 stand/move 目标；一个久坐会话内主动休息与锁屏记账合计最多一次。低于任一门槛只清零，不记账。
验收：29 分钟时锁屏 10 分钟 → 不抵扣；31 分钟时锁屏 4 分钟 → 不抵扣；31 分钟时锁屏 6 分钟 → 抵扣一次；同一会话再点「起来走走」→ 不再抵扣。

**B-7 自动空闲不记账**
普通空闲 ≥15 分钟只清零久坐时钟、记录休息事件，不写 CheckIn、不抵扣目标。只有用户主动确认（起来走走/完成休息流程）与满足条件的锁屏才记账。
验收：午休离开 40 分钟不产生完成记录；锁屏 6 分钟且已坐 31 分钟才产生一条 `source=lock_break` 的完成记录。

**B-8 今天先这样**
用户从软提醒的「更多」选择「今天先这样」后：当日不再出现久坐软提醒、记忆气泡与久坐情绪变化；正式提醒照常；久坐时钟可以继续记录，但不冒泡。次日恢复。
验收：选择后宠物不再因久坐冒泡、情绪回到中性；正式站立/喝水提醒仍按计划出现；跨日后功能恢复。

**B-9 重启与崩溃**
久坐时钟、专注会话、当前气泡是运行期状态，重启后从新会话开始；今日累计从已持久化会话的 `active_seconds` 重新计算。启动时把上次未关闭的应用/久坐会话收尾到最近一次心跳时间并标记 `abandoned`，不把停机时间算作用机。
验收：运行中强杀进程，重启后今日累计不超过崩溃前最后心跳；没有一条持续到「现在」的假会话；今日气泡预算与静音状态从持久化数据恢复。

**B-10 与场景/提醒的关系**
只有在启用场景内至少存在一条启用的 stand/move 提醒、且当前时间落在至少一条此类提醒的生效时段内时，久坐感知才工作。没有场景、没有 stand/move、或所有相关时段都已结束时：不采样应用画像、不冒泡、不抵扣；已有数据仍可在久坐页查看。
验收：只有喝水提醒的场景不出现久坐软提醒；停用场景后不再采样；重新启用带 stand/move 的场景后恢复。

**B-11 暂停、静默与演示**
会议、全屏、锁屏、专注、日历、演示模式、静默时段与「用户正在输入」都不产生久坐冒泡。久坐时钟在会议/全屏/演示期间仍可继续（用户可能一直坐着），但恢复后要等一个自然停顿再开口；锁屏/休眠按真实休息处理。
验收：2 小时会议期间无软提醒；会后焦点回到编辑器并停顿后，若仍超阈值才冒泡；静默时段无冒泡。

**B-12 被动场景的诚实降级**
读长文、看视频等「手没动但可能在坐」的场景，统一走分级空闲：5–15 分钟暂停、≥15 分钟清零。产品接受这部分久坐被低估，由正式站立/走动提醒兜底；文案不得声称能判断真实坐姿。
验收：全屏看视频 40 分钟不产生久坐软提醒；正式提醒依既有暂停规则处理；久坐页的说明明确写着「基于键鼠活跃度的连续用机估算」。

**B-13 宠物情绪三态**
久坐时长映射情绪：`energetic`（<45 分钟）、`concerned`（45–89 分钟）、`droopy`（≥90 分钟）；真实休息后回到 `energetic` 并给一次轻庆祝。情绪只改变芽/眼睛/呼吸等现有视觉层，不新增素材；等待、庆祝等瞬时动作优先于情绪。
验收：45 分钟时芽开始担心下垂；90 分钟明显耷拉；点「起来走走」后恢复；有待处理提醒时仍显示等待动作，情绪层不抢状态。

### C. 与定时提醒结合

**C-1 软提醒阈值与重复**
默认坐到 60 分钟、且 15 分钟内没有 stand/move 提醒时，生成一条久坐软提醒。完全不理则在 90 分钟（或首次展示后 30 分钟，取较晚者）再生成一次；每个久坐会话最多 2 条软提醒。阈值为 45/90 时按同一规则平移。
验收：60 分钟且下一条 stand/move 在 20 分钟后 → 冒泡；下一条在 10 分钟后 → 不冒泡，让正式提醒承担；忽略第一条后 90 分钟出现第二条；第二条后不再冒泡。

**C-2 只在空档开口**
软提醒必须同时满足：没有更高优先级气泡、没有待处理提醒、没有休息预警/倒计时、没有暂停、没有静默、不是专注会话、用户处于自然停顿。任一不满足就等待；等待期间不消耗预算、不产生多次重复。
验收：专注写代码时不冒泡；等到切出应用并停顿后最多出现一条；有待处理提醒时不冒泡，处理完后仍超阈值才补一条。

**C-3 主动发言总预算**
每天最多 5 次宠物主动开口，包含久坐软提醒与独立记忆气泡；软提醒每个久坐会话最多 2 次。两次主动发言至少间隔 30 分钟。正式提醒、休息流程、用户主动点击与欢迎回来不占预算。
验收：当天已展示 5 次后，不再有新的软提醒/记忆气泡；第 5 次之后即使坐到 120 分钟也不冒泡；第二天预算重置。

**C-4 再坐 10 分钟**
软提醒的「再坐 10 分钟」把下一次软提醒延后 10 分钟；仍计入该会话的最多 2 次；不延后正式提醒。
验收：点「再坐 10 分钟」后 10 分钟内不再冒泡；10 分钟后若仍满足条件再冒一次；下一条正式提醒时间不变。

**C-5 真实休息后的静默跳过**
一次真实休息（主动/锁屏/≥15 分钟空闲）发生后 10 分钟内到点、尚未投递的 stand/move 触发点静默跳过：落 `FireSilent`，不发通知、不进待处理、不算错过、不写 CheckIn。只影响 stand/move 的计划触发点，不影响喝水/护眼/如厕/一次性，也不跳过用户主动「推迟」后到点的补发——推迟是用户明确要求，必须照常送达。
验收：休息后 3 分钟到点的站立提醒不弹；同一时刻的喝水提醒照常；没有新增 CheckIn；日志记录跳过的提醒 ID 与触发时刻。

**C-6 主动休息抵扣目标**
用户点「起来走走」或完成休息流程后，抵扣当前场景内最近到点的 stand/move 提醒一次：优先补完当前场景内已存在的待处理 stand/move；否则选择今天仍有剩余触发点（`NextFireAt` 落在今天）的 stand/move 中下一条最先到点的那条，写一条 `source=active_break` 的 `ActionDone` CheckIn。一个久坐会话只抵扣一次；没有可用 stand/move 时不写 CheckIn。
验收：点「起来走走」后首页该提醒完成数 +1；目标可能超额；同一会话再休息不重复加；只有喝水提醒时不产生完成记录。抵扣的检查与写入在同一个数据库事务里完成，active break 与解锁记账并发时也只会成功一次。

**C-7 锁屏抵扣目标**
满足 B-6 门槛的锁屏在解锁时按 C-6 的同一选择规则写一条 `source=lock_break` 的完成记录，并广播 `reminder:changed`；一个久坐会话内与主动休息合计最多一次。
验收：锁屏抵扣后首页进度刷新；主动休息后同一会话再锁屏不再抵扣；跨午夜锁屏按解锁当天记 DateKey，不追溯改昨天。

**C-8 抵扣与跳过的叠加**
同一次休息可以既抵扣一条提醒、又让它 10 分钟内到点的触发点静默跳过；这两件事是「记一次完成」与「不再重复催」，不产生第二条 CheckIn。
验收：59 分钟点「起来走走」，60 分钟到点的站立提醒不弹，首页完成数只 +1。

**C-9 既有提醒语义不变**
一次性提醒、推迟、每日单点、休息模式、强提醒、智能免打扰、自然停顿顺延的行为不变。久坐只额外增加「stand/move 的静默跳过」与「主动休息抵扣」，不重排任何计划时间。
验收：现有 reminder 测试全部通过；一次性提醒照常；喝水/护眼/如厕的触发时间与投递不变。

**C-10 软提醒的交付边界**
久坐软提醒不发系统通知、不弹全屏、不进待处理、不写 CheckIn、不计入今日完成率；它只有宠物气泡一种交付通道。应用未运行、宠物隐藏或演示模式下，软提醒不生成；久坐页仍可查看已记录的久坐数据。
验收：软提醒出现时待处理列表不变、通知中心无新通知、没有任何 CheckIn；隐藏宠物后不再生成软提醒。

**C-11 气泡确认与预算**
`GetSitSnapshot` 返回待展示气泡（带 ID 与过期时间）；`Pet.vue` 真正渲染时调用 `AckSitBubble(id)`。只有已确认展示的软提醒/记忆气泡计入预算与「每会话 2 次」；未被展示而过期的气泡不计数，可以在条件仍满足时重新生成。重复确认幂等。
验收：宠物窗口隐藏 2 分钟后打开，不补发过期气泡；同一 ID 确认两次预算只加 1；预算耗尽后不再生成。

### D. 宠物表现与人格

**D-1 软提醒气泡**
软提醒气泡显示一句结合当前时长的文案、三个入口：「起来走走」「再坐 10 分钟」「更多」。「更多」包含「今天先这样」「别这样说」「打开客户端」，在气泡内展开为第二行动作，不使用会被小窗口裁切的浮层。气泡扩窗沿用现有 `SetPetBubbleVisible` / `SetPetBubbleHeight` 机制；贴边收起时不展示也不确认。气泡不显示场景名（它不是计划提醒），不显示应用名。
验收：气泡按钮可点击且不会触发窗口拖拽；「更多」能打开菜单；按钮动作后气泡收起；文案不含应用名。

**D-2 记忆气泡**
记忆气泡是独立主动气泡，展示一条基于类别级会话/派生规律/完整统计的观察，动作是「知道了」「打开客户端」。它可以引用跳过次数、类别占比、周对比等统计，但不得出现具体应用名。
验收：记忆气泡出现时没有应用名；「知道了」后收起并消耗一次预算；一天最多 5 次主动发言总量。

**D-3 欢迎回来与轻庆祝**
点「起来走走」后宠物进入等待姿态；检测到输入恢复后显示「回来啦」与本次休息时长，并回到精神情绪。欢迎回来是用户动作的反应，不占主动发言预算。
验收：离开 3 分钟回来有欢迎文案；不离开直接输入也有轻量确认，不指责；等待期间没有其他主动气泡抢占。

**D-4 默认毒舌与三档语气**
默认人格是毒舌；设置提供毒舌 / 活泼 / 温和三档。毒舌可以吐槽任何统计（含行为类别、跳过次数、效率、周对比）；活泼可以调侃但不否定人格；温和只关心、不吐槽。切换语气只影响后续文案，不改变计时、统计与隐私边界。
验收：默认设置语气为毒舌；切换后下一次气泡使用新语气；重启后保持；设置中的语气与宠物实际文案一致。

**D-5 别这样说**
任意毒舌气泡的「更多」里提供「别这样说」；点击后立即切到温和语气并持久化，同时给一句温和确认。用户之后可在设置里切回。
验收：点击后当前气泡不再出现毒舌文案；重启后仍是温和；设置页显示温和；再次切回毒舌生效。

**D-6 毒舌硬禁区**
毒舌只针对久坐行为与统计，绝不攻击外貌、智力、心理状态、家庭或健康状况；不做医疗诊断；不阻止或调侃用户就医；不把应用内容/娱乐选择上升为人身评价。任何软提醒/记忆气泡都必须给出一个可执行台阶（起来走走、再坐十分钟、今天先这样、打开客户端），不能只有羞辱。
验收：模板审校与内容护栏通过；不出现身份/健康攻击；每个软提醒气泡都有动作；记忆气泡有「知道了/打开客户端」。

**D-7 文案引擎**
所有宠物台词使用内置模板 + 变量（时长、时段、类别、统计值），不调用 AI、不联网、可复现。模板按语气与场景（软提醒/记忆/欢迎/确认）分组；同一模板在短期内不重复使用。
验收：断网可用；同一输入固定输出；没有 AI 依赖；模板测试覆盖三种语气与所有动作。

**D-8 记忆引用边界**
记忆使用类别级会话与派生规律（时段性久坐、星期规律、主动休息频率、类别分钟数、跳过/推迟次数、正向/负向周对比），不逐条回放原始应用流水。记忆可独立冒泡，但受 5 次/天总预算与 30 分钟间隔约束；专注、暂停、待处理、休息倒计时期间不冒泡。
验收：记忆气泡不出现应用名；不出现「某天 14:03 你打开了 X」这类流水回放；预算与间隔生效。

**D-9 气泡优先级与不抢提醒**
同一时刻只显示一个气泡；优先级为陪做 > 预警 > 顺延 > 演示建议 > 暂停 > 待处理 > 久坐软提醒/记忆。正式提醒、休息流程永远压过宠物主动发言。
验收：有待处理提醒时久坐气泡不出现；处理完待处理后若条件仍满足才出现；休息倒计时期间只有陪做气泡。

**D-10 减弱动态效果**
遵循 `prefers-reduced-motion`：停掉情绪层的常驻循环，保留事件触发的瞬时反馈（欢迎/庆祝），与现有宠物规则一致。
验收：开启系统减弱动态后，情绪不再持续动画；点击/休息回来的反馈仍可见。

### E. 应用画像与久坐页

**E-1 采样与记录**
应用画像开启且久坐感知生效时，每 5 秒读取一次前台应用；只在应用切换、空闲清零、锁屏、功能关闭时落一条会话记录，不按每次轮询写库。排除 Morrow 自身；前台应用读不到时按「未知」处理并记录诊断计数，不写假数据。
验收：一次 30 分钟的 IDE 使用只产生一条会话（除非中途切换）；数据库没有每 5 秒一行的采样流水；读不到前台应用时久坐页显示异常状态。

**E-2 类别映射**
行为类别固定为：写代码 / 做设计 / 浏览 / 沟通 / 影音 / 其他。常见应用用内置名单映射（macOS bundle ID 与 Windows 进程名两份）；会议应用复用现有会议名单归入「沟通」；未知应用归「其他」。类别在读取时派生，不写死在会话行里。
验收：VS Code → 写代码；Figma → 做设计；Chrome → 浏览；Zoom/飞书 → 沟通；未知进程 → 其他；修改内置名单不需要迁移历史数据。

**E-3 用户纠正类别**
久坐页的应用明细里，每个应用可改行为类别；纠正只存本机，立即对所有历史与未来的展示、趋势与宠物记忆生效。
验收：把某浏览器改为影音后，历史类别分布与之后的气泡文案都使用影音；原始应用会话不被改写；清除画像时纠正也删除。

**E-4 久坐页：今日**
新增 `/sit` 页面，侧栏名为「久坐」。今日区域至少展示：当前连续用机时长、当前专注类别与时长（画像开启时）、今日久坐总时长、最长连续久坐、真实休息次数（主动/锁屏/空闲）、已抵扣的 stand/move 次数、站立/走动目标进度（复用 `GetTodayStats`）、行为类别分布、应用明细（应用名、类别、前台时长、会话数）。指标必须有文字标签与口径说明，禁止只放无标签数字。
验收：页面数据与数据库/首页进度一致；每个数字都有标签；没有应用画像时只显示时间类数据；没有数据时有空状态。页面在挂载时、收到 `reminder:changed` 时与可见期间每 30 秒刷新一次；应用切换不会新增事件域。

**E-5 久坐页：7 天与按日查看**
展示最近 7 天的久坐分钟数、最长连续时长、休息次数与主动起身次数；支持按日期查看任意一天的应用明细与类别纠正。趋势用现有设计令牌做 CSS 条形/列表，不引入图表库。
验收：7 天数据与逐日查询一致；日期切换正确；没有新增前端依赖；图表/条形有文字标签。

**E-6 空状态与异常状态**
页面覆盖：无启用场景、场景无 stand/move、应用画像未开启、今天无数据、平台不支持、画像已开启但持续读不到前台应用。每种状态都有明确文案与下一步入口，不能显示成「0 分钟」。
验收：六种状态都能复现并显示对应文案；「读不到应用」与「没有使用」可区分。

**E-7 数据控制**
设置与久坐页提供「清空应用与久坐数据」：删除应用会话、类别纠正、久坐会话/休息、宠物发言记录，清空派生记忆与当前会话；保留已写入的 CheckIn 与连续天数，不追溯改写历史完成率。执行前二次确认。
验收：清空后久坐页为空、宠物不再引用旧记忆；首页完成数与连续天数不变；清空动作幂等。

**E-8 导出数据库时询问**
导出时提供「包含应用使用明细（应用名与时长）」选项，默认勾选并提示「分享给他人前请取消」。取消时导出的库不包含应用会话、类别纠正、久坐会话/休息与宠物发言；`check_ins` 与其 `source` 保留（不含应用名）。恢复两种库都能正常迁移。
验收：勾选导出包含明细；取消导出后打开副本查不到应用会话；恢复后应用可用；现有导出/恢复测试通过。

**E-9 保留期限**
应用与久坐明细保留至用户手动清空或关闭画像时选择删除；不自动过期。数据库只存会话级记录与发言记录，不存 5 秒采样流水；开放会话最多每分钟心跳一次。
验收：运行 7 天后仍能按日查看；没有自动删除任务；数据库体积增长随会话数而非轮询次数。

**E-10 隐私与权限**
应用画像只读前台应用身份（bundle ID / 进程名）、起止时间与类别；不读窗口标题、屏幕内容、键鼠输入内容，不用摄像头/麦克风，不联网上传。日志只记录错误计数/提醒 ID/模板 ID，不记录应用名、原始应用标识或宠物文案全文。数据库与导出文件在支持的平台上使用仅当前用户可读的权限。
验收：权限清单没有新增摄像头/屏幕录制需求；日志抽查无应用名/窗口标题；导出的文件权限受控。

**E-11 采样性能**
5 秒采样器只在功能生效时运行；锁屏/空闲/无场景/总开关关闭时停止或降频；5 秒轮询不写库。macOS 与 Windows 实测空闲 CPU 增量可忽略，不造成明显耗电。
验收：连续运行 1 小时无异常 CPU 占用；数据库写次数与会话切换次数同量级；锁屏后采样停止。

### F. 契约、护栏与文档

**F-1 模型与迁移**
新增模型登记进 `model.AllModels()`；`check_ins.source` 通过 AutoMigrate 增加，默认 `manual`，旧行不受影响。新表使用 `sit_` / `app_usage_` / `app_category_` 前缀，便于导出清理与审计。
验收：旧库升级后启动正常；旧 CheckIn 的 source 为 manual；新表自动创建；`internal/guard` 现有模型注册护栏通过。

**F-2 CheckIn source**
`source` 取值：`manual`（用户从卡片/通知/宠物处理）、`active_break`（主动休息抵扣）、`lock_break`（锁屏抵扣）。统计仍只按 `action=done` 计数，不按 source 改变完成率语义；久坐页可展示 source 分布。
验收：三种来源的完成都进入今日完成数；旧代码写入默认 manual；久坐页能区分主动与锁屏抵扣。

**F-3 前端契约镜像**
`frontend/src/lib/sit.ts` 镜像：状态、情绪、语气、类别、动作 ID、气泡类型、轮询/过期常量；`SitSnapshot` 不含任何应用名字段。`internal/guard/parity_test.go` 双向校验枚举与常量。
验收：改 Go 枚举不同步 TS 时 `make test` 变红；`SitSnapshot` 类型中没有应用名；Pet.vue 只使用镜像常量。

**F-4 不新增事件域**
久坐状态走 `GetSitSnapshot` 轮询；动作走绑定；主动休息/锁屏记账写 CheckIn 后广播既有 `reminder:changed`（reason `check_in`）；不新增 `sit:*` 事件。
验收：事件常量表无新增久坐域；首页/久坐页监听既有事件即可刷新。

**F-5 接线护栏**
`internal/guard/wiring_test.go` 扩展：断言久坐采样器在启动时被接线、关闭时被停止；断言主动休息/锁屏记账路径广播 `reminder:changed`；断言 `GetSitSnapshot`/`AckSitBubble`/动作绑定存在；解析到 0 处即失败并提示同步护栏。
验收：删掉任意一处接线，`make test` 变红；宠物隐藏/平台不支持时有明确降级路径。

**F-6 内容与模板护栏**
模板常量按语气分组；护栏断言每个软提醒模板动作齐全、记忆模板有收束动作、所有模板不含硬禁区词（身份/健康/医疗诊断/侮辱性称呼）；模板审校作为人工验收项。
验收：新增模板若缺少动作或出现禁区词，测试失败；三种语气都有覆盖。

**F-7 依赖与分层**
不新增 Go/前端直接依赖；不引入图表库。`app.go` 绑定层不 import gorm/database；`internal/sit` 不 import Wails；`internal/model` 保持叶子；`internal/guard` 现有分层护栏通过。
验收：`deps.yaml` 不变；`make lint` 通过；分层护栏通过。

**F-8 中文、干净性与文档**
所有新增 UI 文案为中文；无 `console.log`/调试代码；移除临时注释；`make test`、`make lint`、`make smoke` 通过。更新 `docs/map.md`、`README.md`、`docs/pet-character.md`、`openspec/specs/`（新增久坐感知能力基线）与设置页说明。
验收：文档中的产品人格、能力与隐私边界与 ADR 0009–0011 一致；README 不再写「温和陪伴」为默认人格。

## 4. 已定决策

1. **久坐计时是全局时钟，不是逐应用计时。** 切应用不重置；应用画像只做上下文与专注判断（ADR 0009）。
2. **应用画像采用显式同意，全量会话级明细保留至用户删除。** 只存本机、不读窗口标题/内容、不用摄像头、不上传（ADR 0010）。
3. **拒绝画像降级为基础久坐检测。** 仍有时钟、情绪与时间型软提醒；没有类别、专注会话与深度记忆。
4. **分级空闲固定为 0–5 继续 / 5–15 暂停不清零 / ≥15 清零。** 不跟随智能免打扰的空闲阈值设置。
5. **真实休息是清零与跳过的前提。** 主动休息、锁屏、≥15 分钟空闲都算；主动休息与锁屏可抵扣目标，普通空闲不抵扣。
6. **软提醒默认 60 分钟，忽略后 90 分钟（或首展后 30 分钟）再来一次，每个久坐会话最多 2 次。** 阈值可设 45/60/90。
7. **软提醒只在 15 分钟内没有 stand/move 提醒时开口；正式提醒优先。**
8. **每天最多 5 次主动发言，包含软提醒与独立记忆气泡；两次至少间隔 30 分钟。** 正式提醒、休息流程与用户动作不占预算。
9. **真实休息后 10 分钟内到点的 stand/move 触发点静默跳过。** 只影响 stand/move；不发通知、不进待处理、不算错过、不写 CheckIn。
10. **主动休息抵扣最近到点的 stand/move 一次。** 优先补完待处理项；没有可用项时不写 CheckIn；一个久坐会话只抵扣一次。
11. **锁屏 ≥5 分钟且本次已坐 ≥30 分钟才自动抵扣。** 与主动休息共享「一会话最多一次」。
12. **久坐软提醒不发系统通知、不弹全屏、不进待处理、不计打卡。** 它只有宠物气泡；预算按确认展示计数。
13. **默认人格是毒舌，设置三档，气泡内「别这样说」立即切温和。** 毒舌可吐槽任何统计，但硬禁区为身份/心理/健康/医疗诊断，且必须给台阶（ADR 0011）。
14. **记忆使用类别级会话与派生规律，不逐条回放应用流水；气泡不出现应用名。** 具体应用名只在久坐页可见，用户可纠正类别。
15. **文案用内置模板 + 变量，不调用 AI。** 离线、可复现、可审校。
16. **新增「久坐」页：今日 + 最近 7 天 + 按日查看。** 趋势用现有设计令牌的 CSS 条形，不引入图表库。
17. **应用画像只读前台应用身份；不读窗口标题、屏幕内容、键鼠输入内容；不用摄像头；不联网。**
18. **清空应用与久坐数据不追溯改写 CheckIn 与连续天数。** 关闭画像时让用户选择保留或删除历史；导出时询问是否包含明细。
19. **只在有 stand/move 的启用场景、且处于其生效时段时工作。** 没有场景或没有 stand/move 时不采样、不冒泡。
20. **不新增事件域；久坐状态轮询，CheckIn 变更复用 `reminder:changed`。** 不新增通知通道。

## 6. 明确不做

- **摄像头 / 可穿戴 / 真实坐姿检测**：与 ADR 0004 的本地优先与无摄像头边界冲突。
- **屏幕内容、窗口标题、键鼠输入内容**：隐私边界之外。
- **AI 生成宠物台词**：本切片只用内置模板；不联网、不产生不可审校输出。
- **自动重排提醒时间**：久坐只做 10 分钟静默跳过与目标抵扣，不改用户计划的间隔/时刻。
- **接管水/护眼/如厕提醒**：只影响 stand/move。
- **改变一次性提醒语义**：一次性提醒完全不受久坐影响。
- **自动进入休息模式**：软提醒只给气泡与动作；正式休息模式仍由 stand/move/rest 计划驱动。
- **长期分析工具 / 完整历史搜索 / CSV 导出**：本切片只做今日、7 天与按日查看；数据库导出是可选项。
- **聊天式问答**：「我今天坐了多久」不通过对话回答；久坐页直接展示。
- **多场景同时启用**：沿用现有「同一时刻一个场景」。
- **应用黑白名单 / 生产力评分**：不做「该不该工作」的判断。
- **读资料/看视频的特殊计时**：统一分级空闲，接受低估。
- **默认温和 / 首次引导人格二选一**：已定为默认毒舌（ADR 0011）。
- **移动端 / 手表 / 云端同步 / 遥测**：不在本轮。
- **数据库加密**：本轮不做；以本地存储、显式同意、可清空与导出边界作为保护。
- **新事件域**：不新增 `sit:*` 事件。
- **图表库**：不引入新的前端直接依赖；趋势用 CSS 绘制。

## 7. 补充说明

### 7.1 状态机

| 状态 | 进入 | 行为 | 退出 |
|---|---|---|---|
| `idle` | 默认 / 真实休息后 / 无有效场景 | 不采样或只等下一次活动 | 首次输入/应用切换 → tracking |
| `tracking` | 有效场景内开始用机 | 计时、情绪、专注判定、软提醒策略 | 真实休息 → idle；主动休息 → break_wait；总开关/场景失效 → idle |
| `break_wait` | 点「起来走走」 | 等待输入恢复；不冒泡其他久坐内容 | 输入恢复 → tracking + 欢迎 |
| `muted` | 「今天先这样」 | 当天不再冒泡/改情绪；正式提醒照常 | 次日 00:00 → idle/tracking |
| `unsupported` | 平台不支持 / 读取能力缺失 | 不影响正式提醒 | 能力恢复后重启/下一 tick |

- 久坐会话 = `tracking` 的一段；主动休息/锁屏/空闲清零都会结束当前会话。
- 同一会话的主动休息与锁屏抵扣合计最多一次；记录在 `sit_sessions.credited_check_in_id`。
- 崩溃/重启不会把停机时间算入；开放会话按最近心跳收尾。

### 7.3 数据模型（建议）

- `app_usage_sessions`：`id`, `platform`, `app_id`, `started_at`, `ended_at`, `last_seen_at`, `date_key`, `end_reason`（`app_switch` / `idle` / `lock` / `feature_off` / `abandoned`）。
- `sit_sessions`：`id`, `started_at`, `ended_at`, `last_seen_at`, `active_seconds`（真正累计的久坐秒数，不含 5–15 分钟暂停；开放会话按心跳更新）, `date_key`, `end_reason`（`active_break` / `lock_break` / `idle_break` / `feature_off` / `abandoned`）, `credited_reminder_id`, `credited_check_in_id`。今日久坐总时长与最长连续久坐都用 `active_seconds`；前台应用时长是另一套口径，页面必须分别标注。
- `sit_breaks`：`id`, `sit_session_id`, `at`, `kind`（`active` / `lock` / `idle`）, `duration_sec`, `credited_reminder_id`, `credited_check_in_id`。
- `sit_speeches`：`id`, `date_key`, `sit_session_id`, `kind`（`nudge` / `memory` / `greeting`）, `template_id`, `text`, `created_at`, `acked_at`, `expires_at`。预算按 `acked_at` 非空且 kind 为 nudge/memory 计数；发言文本只在本机。
- `app_category_overrides`：`platform`, `app_id`, `category`, `updated_at`，唯一键 `(platform, app_id)`。
- `check_ins.source`：`manual`（默认）/ `active_break` / `lock_break`；统计仍按 `action=done`。现有 `act` 的事务抽出一个带 source 的内部入口，手动打卡传 `manual`，主动休息/锁屏传对应 source。
- 所有模型注册进 `model.AllModels()`；新表用 `sit_` / `app_usage_` 前缀，导出取消时整表删除。

### 7.4 绑定契约（建议）

- `GetSitSettings() / SetSitSettings(in)`：总开关、阈值、语气；返回 `enabled` / `profile_enabled` / `profile_asked` / `threshold_minutes` / `tone` / `platform_supported` / `profile_status`（ok / unsupported / read_error / no_data）/ `muted_today`。画像开关单独走同意/关闭流程。
- `SetSitProfileEnabled(enabled bool, deleteHistory bool)`：同意开启、关闭并保留、关闭并删除；写入 `profile_asked=true`。
- `GetSitSnapshot() SitSnapshot`：至少包含 `state`、`mood`、`continuous_minutes`、`today_sitting_minutes`、`longest_session_minutes`、`profile_enabled`、`profile_supported`、`platform_supported`、`muted_today`、`budget_remaining`、`focus`（类别 + 分钟；无应用名）、`bubble`；**不含应用名**。
- `AckSitBubble(id string) bool`：确认气泡已展示；幂等；只对 nudge/memory 计预算。
- `TakeActiveBreak(bubbleID string) SitActionResult`：清零、记录休息、按规则抵扣、广播 `reminder:changed`。
- `SnoozeSitNudge(bubbleID string) SitActionResult`：延后 10 分钟。
- `MuteSitToday() SitActionResult`：当天静音；给一句确认。
- `SetSitTone(tone string) SitActionResult`：切换语气；给一句确认。

`SitActionResult`：`ok`、`message`（用于宠物/页面展示的中文回执）、`credited`、`credited_title`（被抵扣的提醒标题，可空）。前端只展示 `message`，不自行拼接业务结论。
- `GetSitDay(date string) SitDay`：今日/指定日的久坐、休息、类别、应用明细、抵扣。
- `GetSitTrend(days int) []SitDaySummary`：最近 N 天（首版 7）。
- `SetAppCategory(platform, appID, category string) error`：纠正类别。
- `ClearSitProfile() error`：清空应用与久坐数据，保留 CheckIn。
- 导出：现有 `ExportDatabase` 增加 `includeSitProfile bool`（或新增带选项的方法），前端导出对话框传值。

`SitSnapshot.Bubble`：`id`, `kind`（nudge/memory/greeting）, `title`, `text`, `actions[]`（`start_break` / `snooze_10` / `more` / `dismiss` / `open_app`）, `expires_at`。前端只渲染，不在前端复制模板或类别映射。

### 7.5 类别映射

- 固定类别：写代码 / 做设计 / 浏览 / 沟通 / 影音 / 其他。
- 会议应用复用 `pause` 的会议名单，归入「沟通」；不再维护第二份会议名单。
- 浏览器默认「浏览」（覆盖资料阅读与网页使用）；用户可在久坐页改为影音或其他。由于不读窗口标题，同一浏览器无法按窗口细分，这是已知限制，文案用「浏览」而不是「摸鱼/看视频」。
- 未知应用归「其他」；宠物不会对「其他」发表具体内容评价。
- 类别在读取时派生；纠正覆盖历史与未来视图，不重写原始会话。

### 7.6 记忆与模板

- 派生事实（按本地日期）：时段久坐、星期规律、最长连续、休息次数/类型、主动起身次数、类别分钟数、跳过/推迟次数、正向与负向周对比。
- 记忆机会：专注会话结束、真实休息回来、软提醒（可带一句记忆）、用户打开久坐页（页面内展示，不冒泡）。首版不新增独立定时器；任何满足预算、30 分钟间隔、自然停顿与气泡优先级的 tick 都可以评估一次记忆机会，但只在有值得说的派生事实时才生成。软提醒里的记忆句不额外消耗预算。
- 记忆模板按语气分组；每条必须有收束动作（知道了/打开客户端）；同一模板/事实 3 天内不重复；不与更高优先级气泡争抢。
- 毒舌模板可引用任何统计，但硬禁区由内容护栏 + 人工审校双重保证；软提醒模板必须带动作。

### 7.7 风险与待验证

- **Windows UWP/Store 应用**：现有前台进程名可能是 `ApplicationFrameHost`，无法区分具体应用。实施前做一次 spike；若精度不可接受，未知归「其他」并在久坐页标注，不承诺逐应用精确。
- **macOS 应用身份**：`NSWorkspace.frontmostApplication.bundleIdentifier` 无需新权限；展示名用内置映射，未知显示 bundle ID；不读取窗口标题。
- **5 秒采样与电池**：只在功能生效且画像开启时运行；锁屏/空闲/关闭时停止；实测 CPU/电量。
- **浏览器类别误判**：不读窗口标题导致同一浏览器无法区分工作与影音；用「浏览」中性标签 + 用户纠正 + 不拿具体内容开刀。
- **毒舌人格的首次冒犯**：默认毒舌是产品转向；必须保留显眼的「别这样说」与设置切换，进行真实用户测试与模板审校。
- **导出取消的实现**：现有导出是 `VACUUM INTO` 后改名；取消画像时需要在副本上删除 `sit_*` / `app_usage_*` / 纠正表，再改名；测试恢复路径。
- **数据库增长**：会话级记录 + 60 秒心跳，不按 5 秒写库；长期使用后检查体积与查询性能。
- **Ack/预算的可靠**：宠物隐藏/高优先级气泡会导致气泡过期；预算只按确认展示计数；过期可重生成，避免「没看见却算一次」。
- **锁屏/休眠跨平台**：现有 `LockDetector` 已有平台实现；休眠可能与锁屏不可区分；无法确认锁定时不自动抵扣，只清零。
- **记忆的隐私感**：默认毒舌 + 完整统计可能让用户觉得被审计；用显式同意、可查看、可纠正、可清空、可关闭与「别这样说」缓解；上线后观察关闭率。

### 7.9 首版假设（实现前可再确认）

- **总开关默认开**：新安装与升级用户都会在满足「有 stand/move 的场景」时启用基础久坐检测；升级用户看到的同意卡只针对应用画像，基础检测不另行弹窗同意。若产品希望基础检测也显式 opt-in，需要在 `A-4` / `A-7` 里改默认值，不影响其他语义。
