# A+B「不被打断」切片规格（2026-10-21）

> 目标用户：中文办公人群（见 `CONTEXT.md`）。
> 依据：`docs/competitive-analysis-round2.md`、`CONTEXT.md`、ADR 0001 / 0004 / 0006。
> 范围：A 演示模式 + B 自然停顿顺延，合成一个「不被打断」切片。
> 范围外：严格模式、云端、摄像头、屏幕内容分析、周报、场景模板。
> 状态：代码完成（2026-10-21）；GUI、共享屏幕与真实打字场景待手工验收。实现记录见 `.scratch/uninterrupted-slice/tickets/`。

## 1. 问题陈述

**会议 / 共享屏幕时，用户既可能被打断，也可能被看见。**

Morrow 的智能免打扰能暂停投递，但桌宠、宠物气泡、全屏强提醒是独立的置顶窗口：

- 提醒被暂停后，桌宠仍会出现在共享画面里；
- 强提醒默认全屏，一旦某路信号漏判，整块屏幕的遮罩会被同事看到；
- 没有「演示模式」入口，用户只能临时隐藏宠物或退出应用；
- 竞品有明确的「共享屏幕时暂停」请求（Stretchly #1479、#969），但没有桌宠；Morrow 有载体，却还没有保护。

**打字 / 拖拽时，提醒时机不对。**

- 固定排程到点即弹，强提醒默认全屏；
- 只有「空闲暂停」，没有「正在输入时顺延」；
- Stretchly #189 的原始抱怨就是「写到一半弹出来」；LookAway 把「等待合适时机」作为卖点。

两件事都指向同一个产品承诺：**在该安静的时候，不出现；在该出现的时候，不打断。**

## 2. 方案概述

### 2.1 A：演示模式

演示模式是一个**临时的、最高优先级的暂停原因**，不是另一套投递逻辑：

- 进入后暂停提醒投递（沿用现有暂停语义：周期项顺延不补发、每日单点与一次性记「已错过」）；
- 隐藏桌宠与气泡，已显示的强提醒立即收起；
- 在系统允许时，把桌宠与强提醒窗口排除出屏幕捕获；
- 会议应用或全屏持续 5 秒后，宠物气泡可以建议进入；不自动进入；
- 手动进入直到手动退出；经建议进入的，在触发条件消失 30 秒后自动退出；
- 退出后不补弹演示前的待处理提醒，新提醒照常；
- 不读取屏幕内容、窗口标题，不检测摄像头或麦克风。

### 2.2 B：自然停顿顺延

自然停顿顺延是**投递策略**，不是暂停：

- 非一次性的提醒到点时，若最近 5 秒内有键鼠输入，最多顺延 60 秒；
- 在用户停手后的下一次调度检查（≤20 秒）投递；
- 到 60 秒仍在输入：降级为「安静投递」——系统通知 + 宠物气泡 + 待处理卡片，不弹全屏、不进入休息模式；
- 一次性提醒保持绝对时刻语义，不顺延；
- 顺延只在内存中，应用重启后按正常投递；
- 不新增权限，复用系统空闲时长读取。

### 2.3 共用形状

- 复用现有 `pause.Provider` / `CompositeProvider`：演示模式是一个暂停原因，优先级最高。
- 复用现有 `reminder.Engine.Tick`：顺延在投递前判定，不新建调度器。
- 复用现有 `GetPauseState` 与 `GetReminderSettings/SetReminderSettings`：不新增事件域。
- 宠物、菜单栏、设置页只消费状态，不各自复制规则。

## 3. 用户故事

### A. 演示模式

**A-1 手动进入**
用户可从菜单栏或全局快捷键进入演示模式。菜单栏状态行显示「免打扰：演示中」，菜单项变为「退出演示模式」。重复进入/退出是幂等的。

**A-2 投递暂停**
演示模式期间，周期性提醒按现有暂停语义处理：不投递、不进待处理、恢复后按原间隔重新计时；每日单点与一次性提醒记为「已错过」，保留可见，不补弹。系统通知、强提醒、休息预警都不出现。

**A-3 已有强提醒立即隐藏**
进入演示模式时，如果强提醒正在显示，所有屏幕的遮罩立即收起；待处理记录保留，不自动完成或跳过。

**A-4 桌宠隐藏且不改偏好**
进入演示模式时隐藏桌宠窗口与气泡；不修改用户的宠物显隐设置，不改变贴边位置。退出后按用户原来的显隐偏好恢复；原来隐藏的仍隐藏。

**A-5 屏幕捕获排除**
在平台支持时，桌宠与强提醒窗口不出现在屏幕共享与录屏画面里；主窗口不排除（用户主动打开的内容由用户自己负责）。平台不支持时，演示模式仍可暂停与隐藏，但设置页/菜单栏必须明确显示「当前系统不支持捕获排除」，不能静默失败。

**A-6 会议/全屏建议**
当暂停原因为「会议」或「全屏」持续至少 5 秒，且宠物可见、没有待处理提醒、没有进行中的休息模式、设置允许、本次会话尚未建议过时，宠物气泡显示「在开会/共享屏幕？进入演示模式」与「进入」「不用了」两个动作。建议不发系统通知；用户点「不用了」后，本次会议/全屏会话不再建议。

**A-7 建议进入的自动退出**
经建议进入的演示模式记录来源为「建议」。触发条件（会议或全屏）消失后，等待 30 秒再退出；30 秒内条件重新出现则取消退出。自动退出不弹确认框。

**A-8 手动进入不自动退出**
经菜单栏/快捷键进入的演示模式来源为「手动」，一直保持到用户手动退出；会议/全屏结束不自动退出。

**A-9 退出不补弹**
退出演示模式后，演示前或演示期间产生的待处理提醒不自动弹强提醒；它们仍留在首页待处理区。退出后新到点的提醒照常投递。周期性提醒从退出时刻起按原间隔重新计时。

**A-10 与休息模式的关系**
进入演示模式时，如果休息模式处于预警或倒计时：

- 预警直接取消，不记录；
- 倒计时按「跳过」结束并记录 CheckIn(skip)，不弹「算完成/跳过」确认框；
- 演示期间不进入新的休息模式。

**A-11 暂停原因与优先级**
演示模式在 `PauseReason` 中是独立取值 `presentation`，优先级高于锁屏、专注、日历、会议、全屏、空闲。菜单栏、宠物、设置页都显示「演示中」，而不是「会议中」或「全屏中」。

**A-12 隐私边界**
演示模式只使用前台应用身份、全屏几何、用户主动操作与系统空闲时长；不读取屏幕内容、窗口标题、日历事件内容，不调用摄像头/麦克风，不上传。捕获排除是「不让别人看到窗口」，不是「读取窗口内容」。

**A-13 重启后关闭**
演示模式是临时状态，不写入配置。应用退出/重启后回到关闭状态；如果退出时正在演示，下次启动不自动恢复。

**A-14 设置**
设置页新增「不被打断」区域，包含：

- 演示模式建议：开/关，默认开；
- 演示模式全局快捷键：可配置，默认为空；
- 捕获排除状态：只读（已支持/系统不支持）；
- 自然停顿顺延：关闭 / 30 秒 / 60 秒，默认 60 秒；
- 一段说明：演示模式会暂停提醒并隐藏桌宠/遮罩，不会读取屏幕内容。

不提供「自动进入演示模式」开关（本切片不做自动进入）。

**A-15 快捷键失败不阻断**
演示模式快捷键注册失败（被占用等）只记录日志，不影响启动；设置页如实显示失败状态。与现有「唤起主窗」快捷键的处理一致。

### B. 自然停顿顺延

**B-1 输入中不投递**
非一次性提醒到点时，如果系统空闲时长小于 5 秒（说明用户正在输入），本轮不投递，也不发通知、不弹强提醒、不进入休息模式；记录该触发的顺延开始时间。

**B-2 停手后投递**
之后每轮调度检查（现有 tick ≤20 秒）一次：一旦空闲时长 ≥5 秒，正常投递；用户停手后最迟 20 秒内出现提醒。

**B-3 到上限安静投递**
从首次顺延起满 60 秒仍在输入：按「安静投递」处理——发系统通知（若开启）+ 宠物气泡（若可见）+ 待处理卡片，不弹全屏强提醒、不进入休息模式；`reminder:fired` 载荷带 `quiet_delivery=true`。

**B-4 一次性提醒不顺延**
一次性提醒保持绝对日期 + 时刻语义（ADR 0001），不参与顺延；即使正在输入也照常投递。

**B-5 每日单点与推迟可顺延**
每日单点（`interval_min = 0`）与推迟到点的补发都属于非一次性提醒，适用顺延规则；一次性提醒是唯一例外。

**B-6 不积压、不重复**
同一条提醒的同一个触发点最多投递一次；顺延期间不产生多条通知或卡片；周期网格已有的「只送达最近 1 条，其余记 missed」策略不变。

**B-7 打卡语义不变**
顺延不改变完成/跳过/推迟的语义，也不把提醒提前记为 missed/silent；只有真正投递时才落 fired。用户从宠物/首页/通知处理时，行为与现在一致。

**B-8 演示模式优先**
暂停（含演示模式）优先于顺延：暂停期间不评估顺延，也不投递；进入演示模式时清空内存中的顺延状态，按 A-2 的暂停语义处理。

**B-9 设置**
顺延可关闭（0 秒）或设为 30/60 秒，默认 60 秒；设置变更从下一次到点起生效，已开始的顺延沿用开始时的上限。非法值回落默认值，不阻塞设置保存。

**B-10 可见状态**
顺延期间，如果宠物可见且没有更高优先级的气泡（休息、待处理提醒），宠物气泡显示「等你停下」；不发系统通知。菜单栏不新增顺延状态行，避免状态过载；下一条提醒时间仍显示原计划。

**B-11 重启不保留顺延**
顺延状态只在内存中，不写数据库；应用重启后，到点的提醒按正常规则投递。不新增数据库迁移。

**B-12 平台降级**
系统空闲时长读取不可用时，顺延功能视为关闭，设置页显示「当前平台不支持自然停顿顺延」；提醒按正常规则投递，不报错。

**B-13 日志**
日志记录提醒 ID、开始顺延、实际延迟、是否到上限、是否安静投递；不记录输入内容（也读不到）。

## 4. 已定决策

1. **演示模式是暂停原因，不是第二套投递链路。** 它复用 `pause.Provider` 与引擎的暂停语义；不复制一套「不投递」逻辑。
2. **手动进入直到手动退出；建议进入在触发条件消失 30 秒后自动退出。** 本切片不做自动进入。
3. **捕获排除默认开启，不提供用户开关。** 系统不支持时明确显示降级，不静默。
4. **不做通用的 15/30/60 分钟手动暂停。** 本切片的「手动暂停」就是演示模式；通用暂停留到后续评估。
5. **演示模式不写入配置，不改用户宠物显隐偏好。** 它只改运行期窗口显隐；重启后关闭。
6. **退出演示模式不补弹旧提醒。** 只有退出后新到点的提醒才会触发强提醒。
7. **自然停顿顺延只覆盖非一次性提醒。** 一次性提醒遵守 ADR 0001 的绝对时刻语义。
8. **顺延上限 60 秒，设置档位 0/30/60；状态只在内存。** 不新增数据库迁移。
9. **到上限采用安静投递：通知 + 宠物 + 待处理，不弹全屏、不进休息模式。** 这样既不丢失提醒，也不在用户明显忙碌时抢占屏幕。
10. **菜单栏不新增顺延状态行。** 顺延是短时状态；避免菜单栏状态过载。
11. **不读取屏幕内容/窗口标题，不检测摄像头/麦克风。** 与 ADR 0004、ADR 0006 一致。
12. **不新增事件域。** 状态读取复用 `GetPauseState`，设置复用 `ReminderSettings`，契约字段由 parity guard 校验。
13. **不改休息模式/一次性/智能免打扰的既有语义。** 演示模式与顺延只在各自边界内叠加。

## 5. 测试决策

### 5.1 接缝

优先在高接缝测试，不直接测 Wails 窗口。

1. **`presentation.Controller`（新深模块）**
   - 纯状态机：off / active_manual / active_suggested；触发来源、进入时刻、自动退出宽限期。
   - 输入：底层暂停状态（会议/全屏/其他）、用户动作（进入/退出/忽略建议）、当前时间。
   - 输出：是否 active、来源、建议是否可见、是否应自动退出。
   - 实现 `pause.Detector`，向 `CompositeProvider` 提供 `ReasonPresentation`。
   - 测试：手动进入不自动退出；建议进入在条件消失 30 秒后退出；30 秒内条件恢复则取消；幂等；重启后 off。

2. **`pause.CompositeProvider`**
   - 新增 `ReasonPresentation` 的优先级最高；与其他信号并存时返回 presentation。
   - 测试：锁屏 + 演示 = presentation；会议 + 演示 = presentation；仅演示 = presentation。

3. **`reminder.Engine.Tick`**
   - 注入 fake store、fake provider、fake activity、fake clock。
   - 测试 A-2/A-8/A-9：暂停期间不投递、不补发；退出后新提醒正常。
   - 测试 B-1/B-2/B-3/B-4/B-6/B-7/B-8：输入中顺延、停手投递、到上限安静投递、一次性不顺延、不重复、打卡语义不变、暂停优先。
   - 测试安静投递不进入休息模式、`quiet_delivery=true`。

4. **App 绑定 / 设置**
   - `GetPauseState` 返回 presentation 字段与捕获排除能力；新增 `GetDeferralState`（active / since / supported）供宠物与设置页使用。
   - `GetReminderSettings/SetReminderSettings` 往返顺延设置与建议开关；非法值回落。
   - 宠物有效显隐 = `PetVisible && !presentationActive`；进入/退出不改配置。
   - 强提醒显示规则：演示中不显示；退出后只对 `fire_at > 退出时刻` 的新触发显示；`PendingFire.quiet_delivery` 的条目不显示。

5. **捕获排除**
   - 复用 Wails v3 内置的 `WebviewWindowOptions.ContentProtectionEnabled` / `SetContentProtection(bool)`，不自建 `windowguard` 或 cgo 平台包。
   - 平台支持状态用构建标签判断（macOS / Windows 支持，Linux 等 no-op 并降级）；macOS / Windows 真实窗口手工验证，CI 只验证编译与状态字段。

6. **契约**
   - `PauseReason` 与 `FiredPayload` 的 Go/TS 镜像由 `internal/guard/parity_test.go` 校验；新增字段必须双向对齐。

## 6. 明确不做

- **屏幕内容分析 / 自动识别共享屏幕**：没有可靠的跨平台公开信号，且违反 ADR 0004；本切片只做手动 + 会议/全屏建议。
- **摄像头/麦克风检测**：隐私成本高，误判多；不跟 LookAway 路线。
- **自动进入演示模式**：默认关闭，本切片不提供。
- **通用 15/30/60 分钟手动暂停**：演示模式之外的暂停留到后续；避免本切片变成「又一个暂停按钮」。
- **演示模式持久化**：不写配置，重启即关闭。
- **退出后补弹旧待处理**：不做「积压轰炸」。
- **顺延持久化 / 数据库迁移**：只在内存；重启正常投递。
- **顺延的菜单栏专用状态行**：不新增。
- **捕获排除的用户开关**：默认开启；如未来要录制宠物，再评估。
- **休息模式/一次性/智能免打扰语义变更**：不动。
- **周报、场景模板、统计、云端、账号、严格模式、移动端/手表**：不属于本切片。
- **新事件域**：不新增 `presentation:*`；复用现有契约。

## 7. 补充说明

### 7.1 状态机

| 状态 | 进入方式 | 行为 | 退出 |
|---|---|---|---|
| `off` | 默认 / 重启 | 正常投递 | 手动/建议进入 |
| `active_manual` | 菜单栏 / 快捷键 | 最高优先级暂停；隐藏宠物/遮罩；捕获排除 | 再次点击 / 快捷键 |
| `active_suggested` | 宠物建议「进入」 | 同 manual；记录触发条件 | 条件消失 30 秒后自动退出；用户也可手动退出 |

- 进入演示时若正在休息倒计时：按 skip 结束（A-10）。
- 进入演示时若强提醒可见：立即隐藏（A-3）。
- 退出时记录退出时刻，供强提醒显示规则使用（A-9）。
- 手动进入的 `active_manual` 不因会议/全屏结束而退出；建议进入的才自动退出。

### 7.2 技术风险与待验证点

- **Wails v3 窗口捕获排除**：spike 已确认 Wails v3 beta.23 内置 `ContentProtectionEnabled` / `SetContentProtection`（macOS `NSWindowSharingNone`、Windows `WDA_EXCLUDEFROMCAPTURE`），不需要自建平台包。真实共享屏幕的可见性仍需在 005 / 009 手工验证；Linux 等平台 no-op，按 A-5 降级。
- **共享屏幕没有可靠信号**：本切片不承诺自动识别共享屏幕；建议只基于会议/全屏，用户可手动进入。产品文案不能写「自动检测所有共享」。
- **自动退出误判**：会议应用失去前台不等于会议结束；30 秒宽限 + 菜单栏「自动」状态 + 用户可重新进入，是当前折中。若实测误判高，后续把建议进入也改为手动退出。
- **输入活跃度复用**：`GetIdleDuration` 已存在，不新增权限；Linux 等平台若不可用，按 B-12 降级。
- **宠物气泡优先级**：休息 > 待处理 > 演示建议；有 pending 时不建议，避免建议盖住真正的提醒。
- **强提醒旧触发不重放**：退出演示后用「fire_at > 退出时刻」过滤；这条规则需要在前端 Alert 与测试中固定下来，避免回归成「退出后一次弹多条」。

### 7.4 验证方式

不引入遥测，自用 1–2 周观察：

- 共享屏幕时是否还有桌宠/遮罩泄露；
- 打字时是否还被全屏打断；

- 退出演示后是否出现积压弹窗。
