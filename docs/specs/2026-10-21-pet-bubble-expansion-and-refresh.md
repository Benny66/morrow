# 宠物气泡扩窗与打卡刷新 — 规格说明书

- 日期：2026-10-21
- 来源：`grill-with-docs` 共识（2026-10-21）、`CONTEXT.md`、`docs/adr/0007-pet-bubble-on-demand-expansion.md`
- 状态：ready-for-tickets（供 `to-tickets` 切分垂直切片）

## 1. 问题陈述

**气泡在小缩放下的固定窗口里放不下，内容被从顶部裁掉。**

桌面宠物的窗口尺寸只由 `pet_scale` 决定。`pet_scale = 0.5` 时窗口是 120×190，宠物本体占 104 高，留给气泡的空间只有约 74px；而气泡的字号与内边距不随缩放变小，完整内容需要约 150–180px。`.pet` 是 `justify-content: flex-end` + `overflow: hidden`，不够的部分从顶部裁掉——用户看到的是半行正文、完成/推迟按钮与「打开客户端」，场景名与标题完全消失。这不是长文案的偶发问题，而是 0.5 与 0.75 两档的必然结果。

**点击「完成」看起来无反应，气泡也不会消失。**

日志证据（2026-10-21）：

```text
11:15:01 提醒已送达 reminder=起身活动 rest_mode=true
11:18:26 Binding call failed: Bound method returned an error: 该提醒已处理
11:18:26 处理提醒失败 | {"kind":"done","fire_id":39,...}
```

这条提醒在 11:17 由休息模式倒计时自动完成，后端把它写成 `done`，但 `tickRestMode` 只广播了 `restmode:completed`，没有广播 `reminder:changed`。宠物窗口只在 `reminder:fired` / `reminder:changed` 时刷新待处理列表，于是一直挂着一条早已完成的提醒；每次点击「完成」，后端返回「该提醒已处理」，前端只写一条 warn 日志，UI 不动。看起来就是按钮死了。

**相邻隐患：休息模式会静默卡死在 Done。**

休息倒计时期间，如果用户从宠物气泡、首页卡片或系统通知提前完成这条提醒，倒计时结束时服务端的自动完成会收到「已处理」，`tickRestMode` 保持 `Done` 且不 `Reset`。而状态机只接受从 `Idle` / `Warning` 进入，此后所有休息提醒都静默退化，直到应用重启。

三件事指向同一个产品承诺：**宠物承载的提醒必须看得全、点得动；任何状态都不能在没有症状的情况下失效。**

## 2. 方案概述

### 2.1 气泡：按需临时扩窗

基础尺寸公式不动（`pet_scale = 0.5` 仍是 120×190），不为气泡做任何配置迁移。

气泡可见时：

- 先把窗口加宽到 240（以宠物中心向两边扩；工作区放不下时向内夹取）。
- 下一帧按气泡实测内容高度向上扩；以宠物脚底为锚点，底边不动，宠物在屏幕上保持原位。
- 顶部空间不足时钉住工作区顶边，宠物临时下移；气泡消失后立即恢复基础尺寸与位置。
- 气泡消失即还原；扩窗不写入配置，退出时持久化的是**基础几何**。

同一时刻只显示一个气泡，优先级：**陪做（倒计时）> 预警 > 暂停 > 待处理**。休息倒计时期间不再渲染待处理气泡的完成/推迟按钮。

### 2.2 打卡：事件补齐 + 失败自愈

- 休息模式自动完成后补发 `reminder:changed`，宠物、首页与 store 走同一条刷新路径。
- 宠物气泡内的完成/推迟失败时，重新拉取待处理：若这条已被处理，气泡自然消失并按原逻辑庆祝；若仍在，保留气泡并显示可见错误文案。
- 气泡按钮加 in-flight 防重，避免连续点击风暴。
- 真失败显示「操作失败，请再试一次」，保留「打开客户端」入口。

### 2.3 休息模式：已结算不再卡死

自动完成收到 `validation`（已处理）或 `not_found`（记录不存在）时，视为该会话已结算：照常 `Reset`、广播 `restmode:completed` 与 `reminder:changed`。只有真正的内部错误才保持 `Done` 等待重试。

### 2.4 契约与边界

- 新增两个绑定：`SetPetBubbleVisible(bool)` 与 `SetPetBubbleHeight(total)`；不新增事件域。
- 几何换算收敛为 Go 侧纯函数并加单测；前端只负责实测与上报。
- 贴边吸附、展开位置、退出持久化一律按基础几何计算。

## 3. 用户故事

### A. 气泡布局与扩窗

**A-1 小缩放完整显示**
当 `pet_scale = 0.5` 且有待处理提醒时，气泡的场景名、标题、正文、完成/推迟与「打开客户端」全部可见，顶部不被裁切。
验收：在 0.5 档触发一条提醒，气泡没有任何内容被窗口边缘裁掉；截图与 1.0 档的气泡信息量一致。

**A-2 宠物保持原位**
气泡出现与消失时，以宠物脚底为锚点：窗口向上、左右扩，宠物本体的屏幕位置不变（水平方向仅在屏幕边缘夹取时临时偏移）。
验收：记录宠物在屏幕上的中心与底边坐标；气泡出现前后坐标不变（无夹取时），消失后恢复。

**A-3 宽度与边缘夹取**
气泡可见时窗口宽度临时到 240；横向以宠物中心对称扩。目标宽度超出所在屏幕工作区时，窗口向内夹取，夹取后按实际宽度重新排版与测量。
验收：把宠物放在屏幕右缘触发提醒，气泡完整落在工作区内；文字按夹取后的宽度换行，不横向溢出。

**A-4 高度按实测增减**
窗口高度等于「宠物 + 间距 + 内边距 + 气泡实际高度」。下一条提醒文案更短时窗口随之变矮，更长时随之变高；不需要重新显示气泡。
验收：连续处理两条长度差异明显的提醒，气泡高度跟随内容变化，没有留下上一条的高窗口。

**A-5 气泡消失即还原**
待处理清空、气泡切换到无内容、或宠物窗口隐藏时，窗口立即回到基础尺寸与基础位置；不残留扩出来的透明区域。
验收：点完成最后一条后，窗口尺寸回到 120×190（0.5 档）；没有「看不见但点不到」的残留区域。

**A-6 单一气泡与优先级**
同一时刻只显示一个气泡，优先级为陪做（倒计时）> 预警 > 暂停 > 待处理。休息倒计时期间只显示「陪你休息 mm:ss」，不显示待处理气泡及其按钮。
验收：倒计时期间宠物上只有一个气泡；倒计时结束后若仍有待处理，按优先级显示对应气泡。

**A-7 贴边收起与展开**
宠物贴边收起时气泡不显示、窗口不扩；鼠标划过展开后，先回到基础几何，再按 A-1 扩窗。贴边吸附与「展开位置」的判断使用基础矩形，不因扩窗误判为用户拖动。
验收：宠物收起在屏幕边缘 → 悬停展开 → 气泡完整显示；静置后能正常再次收起，不会因扩窗位置变化而立刻重新吸附。

**A-8 退出与重启**
气泡可见时退出应用，写入配置的是基础矩形；下次启动宠物出现在退出前的基础位置，不下移、不偏移。
验收：0.5 档、气泡可见时退出 → 重启 → 宠物位置与退出前一致；`config.json` 的 `pet_x/pet_y` 对应基础窗口。

**A-9 缩放设置变化**
气泡可见时在设置页修改缩放：基础尺寸立即更新，扩窗按新的宠物尺寸重新贴合，宠物底边保持锚定。
验收：0.5 → 1.0 切换时气泡仍完整；宠物不跳到屏幕外。

**A-10 屏幕空间不足**
窗口向上扩会超出工作区顶边时，钉住工作区顶边并向下扩，宠物临时下移；气泡消失后恢复。内容仍然放不下时，优先保证底部按钮与「打开客户端」可见，顶部文案按可用高度裁切。
验收：把宠物放在屏幕顶部触发长文案提醒，操作按钮仍可点击；气泡消失后宠物回到原位。

**A-11 多屏**
扩窗以宠物脚底所在屏幕的工作区为边界；跨屏摆放时不使用主屏尺寸夹取。
验收：宠物在副屏触发提醒，气泡完整落在副屏工作区内，不被主屏边界截断。

**A-12 拖拽手势期间**
用户正在按住/拖动宠物时，不因气泡出现或文案变化而改变窗口几何；手势结束后再应用扩窗。
验收：拖动过程中到点，宠物不跳、不抢鼠标；松手后气泡完整显示。

**A-13 不抢焦点**
扩窗与还原不激活宠物窗口、不抢键盘焦点、不把宠物置前到其他应用之上（保持原有 `AlwaysOnTop` 层级即可）。
验收：在其他应用输入时触发提醒，光标与输入焦点不跳走。

**A-14 收敛**
宽度被工作区夹窄后，按实测高度再次调整；同一尺寸的重复上报不产生反复 resize。
验收：夹窄场景下最多两次调整后稳定；日志中没有持续刷屏的 resize 调用。

### B. 打卡与刷新

**B-1 自动完成广播 changed**
休息模式倒计时自动完成后，除 `restmode:completed` 外必须广播 `reminder:changed`（原因 `check_in`）。宠物、首页与 store 都据此刷新。
验收：倒计时结束后宠物气泡消失并庆祝；首页待处理数量归零；日志只有一条完成记录，不出现「该提醒已处理」的循环。

**B-2 气泡内处理成功**
在气泡里点完成或推迟成功后，立即刷新待处理；完成最后一条时播放庆祝动画。
验收：点击后气泡内容切换或消失；完成最后一条时宠物切换为 `jumping`。

**B-3 已处理自愈**
气泡里的动作失败时，先重新拉取待处理。若当前这条已不在列表（已被别处处理），气泡消失，不显示错误；若列表为空，按 B-2 庆祝。
验收：复现「休息自动完成后点完成」的旧场景，气泡自行消失，不再需要用户反复点击。

**B-4 真失败可见**
动作失败且这条仍在待处理时，气泡内显示「操作失败，请再试一次」；保留完成/推迟与「打开客户端」。错误文案在下一次动作开始、待处理变化或气泡切换时清除。
验收：模拟数据库错误，用户能在气泡里看到失败提示；重试成功后提示消失。

**B-5 防重**
一次动作在途时，完成/推迟按钮禁用；重复点击不产生第二次绑定调用。
验收：快速连点 10 次，后端只收到 1 次完成请求。

**B-6 刷新消费者一致**
`reminder:changed` 的既有消费者（首页待处理、首页已错过、store、Alert 窗口）不需要新增订阅即可同步。
验收：自动完成后切到首页，待处理与「已错过」均与数据库一致。

### C. 休息模式

**C-1 自动完成成功**
倒计时归零、CheckIn 落库成功：状态 `Countdown → Done → Reset`，广播 `restmode:completed` 与 `reminder:changed`。
验收：覆盖层收起；宠物气泡按 B-1 消失并庆祝；日志为 Info。

**C-2 已结算**
自动完成收到 `validation` / `not_found`：视为已结算，照常 `Reset` 并广播两个事件；日志为 Info，不产生 warn 噪声。
验收：倒计时期间从通知点完成，倒计时结束时状态回到 `Idle`，不卡在 `Done`。

**C-3 内部错误保持可重试**
自动完成收到 `internal` 等真实错误：保持 `Done`，不 `Reset`，记 warn；下一轮 tick 重试。
验收：模拟数据库错误后恢复，下一次 tick 完成结算；没有丢 CheckIn。

**C-4 后续会话可进入**
C-2 之后再次到点的休息提醒能正常进入预警与倒计时，不因上一次的已结算而失效。
验收：连续两条 stand 提醒，第一条在倒计时中被通知完成，第二条仍能进入休息模式。

### D. 契约与验证

**D-1 绑定契约**
`SetPetBubbleVisible(bool)` 与 `SetPetBubbleHeight(int)` 写在 `app.go`；生成的绑定产物同步更新，`internal/guard/bindings_test.go` 通过。
验收：`make gen` 后绑定 ID 与 Go 方法一致；护栏无「产物过期」报错。

**D-2 不新增事件域**
不新增 `pet:bubble` 等事件；扩窗只走绑定，刷新只走既有 `reminder:fired` / `reminder:changed` / `restmode:completed`。
验收：事件常量表无新增宠物域条目。

**D-3 无声失效护栏**
扩展 `internal/guard/wiring_test.go`：断言休息自动完成的结算路径同时广播 `reminder:changed` 与 `restmode:completed`；解析到 0 处即失败并提示同步护栏规则。
验收：删掉任意一处广播，`make test` 变红。

**D-4 日志**
- 已结算：`休息模式自动完成：该提醒已结算，视为完成 fire_id=...`（Info）。
- 真失败：保留现有 warn，并带 fire_id。
- 扩窗：不逐次记录；仅在尺寸应用失败时 warn。
验收：按日志能区分「结算」与「真失败」。

## 4. 已定决策

1. **基础尺寸公式不动**，扩窗只在气泡可见期间发生；不做配置迁移。
2. **以宠物脚底为锚点**向上/左右扩，宠物保持原位；顶部不够时钉住顶边、宠物临时下移。
3. **目标宽度 240，按宠物中心对称**；工作区放不下时向内夹取，再按实际宽度测量高度。
4. **高度按实测，不设固定预算**；允许随文案变短而缩小。
5. **同一时刻只显示一个气泡**：陪做 > 预警 > 暂停 > 待处理；倒计时期间不显示待处理按钮。
6. **扩窗不持久化**；退出时把当前窗口反算回基础矩形，贴边吸附/展开也按基础矩形计算。
7. **拖拽手势期间不扩窗**，手势结束后再应用。
8. **休息自动完成必须广播 `reminder:changed`**，与 `restmode:completed` 一起。
9. **宠物打卡失败先自愈再提示**：重新拉取待处理；已被处理则静默收起，仍在才显示错误文案。
10. **气泡按钮加 in-flight 防重**，在途时禁用。
11. **休息自动完成的 `validation` / `not_found` 视为已结算**，照常 `Reset` 并广播；只有内部错误保持 `Done` 可重试。
12. **不新增事件域**；扩窗用绑定，刷新复用既有事件。
13. **不引入新依赖**，不新增前端状态库或测试框架。

## 5. 测试决策

### 5.1 接缝

优先在高接缝测试，不直接测 Wails 窗口。

1. **扩窗几何（Go 纯函数，新接缝）**
   - 输入：基础矩形、基础尺寸、目标宽高、工作区矩形。
   - 输出：扩窗后的窗口矩形；以及从当前（可能已扩大的）矩形反算基础矩形。
   - 规则：底边锚定、横向以基础中心对称、横向夹取到工作区、顶部不足时钉住顶边。
   - 测试：0.5 / 1.0 / 2.0 三档；贴右缘、贴上缘、副屏、缩回、幂等调用。

2. **休息结算分类（Go 纯函数，新接缝）**
   - `settled(err) bool`：`apperr.CodeValidation` / `apperr.CodeNotFound` → true；`internal` / 其他 → false；nil 由调用方按成功处理。
   - 测试：四种错误码 + 包装后的错误（`apperr.Wrap`）。

3. **自动完成的事件接线（源码护栏）**
   - 在 `internal/guard/wiring_test.go` 中解析休息自动完成的结算路径，断言同时包含 `emitReminderChanged` 与 `restmode:completed` 广播。
   - 解析到 0 处必须失败，并提示「写法可能已变更，请同步更新护栏解析规则」。

4. **绑定护栏**
   - 两个新绑定写在 `app.go`；`make gen` 后由 `internal/guard/bindings_test.go` 复算 ID 对账。

5. **前端测量与交互（手工 + 冒烟）**
   - 无前端单测框架：测量逻辑抽成 `lib/pet.ts` 或 Pet.vue 内的纯函数（输入为气泡高度、宠物高度、内边距、间距），至少保证输入输出可读、可复用。
   - 手工在 0.5 / 1.0 / 2.0 三档验证 A-1 ~ A-14；`make smoke` 验证启动链路。

## 6. 明确不做

- **不改基础尺寸公式、不做常驻大窗**：扩窗只在气泡可见时发生。
- **不把气泡字号/间距等比缩小**：0.5 档仍保持可读字号。
- **不做固定气泡预算**：高度按实测，避免长标题被固定省略。
- **不做窗口 resize 动画**：接受一次瞬时跳动。
- **不把气泡拆成独立窗口**，不堆叠多个气泡，不做气泡内滚动/富文本。
- **不做宠物待处理的 4 秒轮询**：刷新只靠事件与失败自愈。
- **不改系统通知按钮的行为**：通知完成仍直接调服务层；本规格只补事件与状态机结算。
- **不改休息模式时长、引导动作与预警文案**。
- **不修复 Alert 窗口「做完了」块的可见性**：这是既有行为，与本切片无关。
- **不新增事件域、不新增依赖、不新增前端测试框架**。
- **不处理演示模式 / 自然停顿顺延**：属于 `2026-10-21-uninterrupted-slice.md`；本规格只保证气泡优先级链可容纳后续类型。

## 7. 补充说明

### 7.1 证据与数值

- 截图对应 `pet_scale = 0.5`：窗口 120×190，宠物 104 高，气泡可用约 74px。
- 气泡完整内容在 240 宽下约需 150–180px；当前 0.5 档必然裁切。
- 日志：`11:15:01` 送达（`rest_mode=true`），`11:18:26` 起连续「该提醒已处理」；`fire_id=39` 的状态为 `done`。
- 休息模式 stand 倒计时 120 秒（`internal/restmode/cue.go`），因此完成发生在点击之前。

### 7.2 扩窗时序与契约

1. 任一气泡挂载 → `SetPetBubbleVisible(true)`：Go 加宽到 240（夹取后可能更窄），高度维持基础值。
2. 下一帧 → 前端测量绝对需求：`气泡高度 + 间距 + 宠物高度 + 上下内边距`，调 `SetPetBubbleHeight(total)`。
3. 文案变化 / 宽度被夹窄 → `ResizeObserver` 重新测量；相同数值不重复上报。
4. 气泡卸载 / 无内容 → `SetPetBubbleVisible(false)`：恢复基础尺寸与位置。
5. Go 侧保存「气泡预算 = total - 当前宠物高度」；缩放变化时用新宠物高度重算总高，前端随后再校准。

- 目标宽度 240 是 Go 侧常量，前端不复制。
- 基础矩形由当前矩形反算：`baseX = curX + (curW - baseW)/2`，`baseBottom = curY + curH`。
- 扩窗不使用 `InitialPosition`；一律 `SetSize` + `SetPosition` 成对应用，避免先大后小的一帧跳变。

### 7.3 与既有切片的关系

- 气泡优先级链：陪做 > 预警 > 暂停 > 待处理；`uninterrupted-slice` 的「演示建议」与「顺延提示」排在待处理之后。
- 该切片中的「休息 > 待处理 > 演示建议」与本规格兼容：休息 = 陪做 + 预警；演示建议仍在最后。
- 演示模式隐藏宠物时不扩窗；退出演示后按当前待处理状态重新决定气泡。

### 7.4 风险与平台差异

- **窗口 resize 抖动**：`SetSize` + `SetPosition` 在不同平台的合成时机可能不同；以一次成对调用为准，实测有闪动再评估逐帧方案。
- **焦点**：扩窗不应激活窗口；若某平台 `SetSize` 会置前，需记录并按平台降级。
- **贴边监测**：位置轮询依赖「连续两次采样相同」判定拖动结束；扩窗会改位置，必须按基础矩形比较，避免自我触发。
- **长文案**：极端长标题会让窗口接近工作区高度；此时优先保证按钮与「打开客户端」可见，顶部文案按可用高度裁切，属于有意的降级。
