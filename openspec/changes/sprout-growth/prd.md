# 增量 PRD — 宠物「小满」芽随今日完成率生长

## 产品目标

让桌面宠物「小满」头顶的芽**反映「今天整体做得怎么样」**：今日完成率越高，芽长得越足。
用户无需打开主窗口，看一眼桌角的宠物就知道今天进度如何——把「打卡」这个被动的完成动作，
变成「看着它长大」的持续正反馈。

一句话：**芽是今日进度的化身，当天生长、次晨归零。**

## 用户故事

- **作为用户**，我完成了几次提醒后，看到桌角的芽明显长大了一截，知道「今天有进展了」，
  被激励继续完成剩下的目标。
- **作为用户**，我跨过 100% 的那一下，芽完全展开并短暂庆祝，让我明确知道「今天达标了」。
- **作为用户**，我一天还没开始（完成率 0），看到芽是安静的小芽苗而不是「枯死/错误」，
  不会误以为哪里出了问题。
- **作为用户**，我的计划里没有设目标（TargetTotal=0），芽保持一个稳定的「健康小苗」姿态，
  不会被误导成「今天表现很差」。

## 需求池

### P0（本变更必须做）

| 编号 | 需求 | 说明 |
|---|---|---|
| R1 | 宠物窗口能读到「今日完成率」 | 复用 `GetTodayStats` 的 `DoneTotal`/`TargetTotal`，经只读绑定方法或现有轮询送达宠物窗口 |
| R2 | 芽按完成率分段生长 | 完成率映射到若干生长档位（见下方映射表），视觉由芽的叶子/茎/挺立度表达 |
| R3 | 完成率变化驱动芽更新 | 收到 reminder:changed 事件或 4 秒轮询时刷新，不新增事件常量 |
| R4 | 边界与降级 | TargetTotal=0 / DoneTotal=0 / 数据读不到，各有一致的非误导表现 |

### P1（可后续）

| 编号 | 需求 | 说明 |
|---|---|---|
| R5 | 跨过 100% 的强化庆祝 | 在 R2 基础上，从 <100% 跨到 =100% 时触发一次「完全展开 + 微闪光」，区别于普通生长 |
| R6 | 芽生长的平滑过渡 | 完成率跳变时芽用 300ms 过渡而非瞬切（需评估与现有 CSS 动画的冲突） |

### P2（暂不做）

| 编号 | 需求 | 说明 |
|---|---|---|
| R7 | 芽随连续打卡天数（streak）生长 | 语义与「今日完成率」不同，属另一套激励，暂缓 |
| R8 | 身体水位线 | 静态半截水位会被读成「画错的肚皮」，需更完整设计 |
| R9 | 用户可调生长档位/阈值 | 过度设计，先固定档位 |

## 完成率 → 芽形态 分段映射（核心）

完成率 = `DoneTotal / TargetTotal`（TargetTotal>0 时）。

| 档位 | 完成率区间 | 芽形态 | 设计意图 |
|---|---|---|---|
| 0 | = 0 | 小芽苗：两片小叶，茎短，微微内收 | 「新的一天刚开始」，安静、不枯、不慌 |
| 1 | 1% – 33% | 芽挺立，叶子展开一个小角度 | 有一点进展，给出「在长了」的正反馈 |
| 2 | 34% – 66% | 茎变高，叶子展开更大，叶子颜色饱满 | 过半，明显「长了一截」 |
| 3 | 67% – 99% | 茎更高，两片叶完全展开 | 接近达标，「再加把劲」 |
| 4 | 100% | 完全展开：茎最长、叶全开、姿态最精神 | 达标，完整形态 |

**为什么是 5 档而不是连续百分比**：
- 完成率本身是离散跳变的（点一次完成 +1 次，目标通常是 6–10 次，一步就跨好几个百分点），
  连续映射的「平滑生长」在视觉上只会变成一顿一顿的抽搐，反而破坏「生长」的体感。
- 5 档足够区分「没开始 / 有一点 / 过半 / 快完成 / 达标」五种用户真实关心的心理节点。

**为什么边界用「今日完成率」而不是「累计完成次数」**：完成率归一化到 0–100%，
跨不同目标规模（今天 6 杯水 vs 今天 12 次起身）体验一致，不会因为目标数量不同
让「同样的努力」长出「不同大小的芽」。

## 状态变化体验

- **生长是「跳档」而非「平滑百分比」**（见上），但档位切换本身用 300ms 缓动过渡，
  避免肉眼可见的生硬跳变（R6，P1 可选；若与现有 pet-sprout 动画冲突，P0 阶段先瞬切）。
- **跨 100% 的庆祝**（R5，P1）：从 <100% 到 =100% 的瞬间，复用/强化既有的「庆祝」情绪
  （jumping 状态已经会甩芽），但注意**不要**与「待处理清空时的 jumping」混淆——
  两者触发语义不同，需在 PRD 里区分清楚（交给架构师定夺信号复用方式）。

## 边界与降级

| 情况 | 芽表现 | 理由 |
|---|---|---|
| TargetTotal = 0（未设目标） | 固定「健康小苗」档（档位 0 的形态，但不暗示「没开始」） | 完成率无定义，不能判「很差」 |
| DoneTotal = 0 且 TargetTotal > 0 | 档位 0（小芽苗） | 今天还没开始，正常状态 |
| 数据读不到（绑定失败/引擎未就绪） | 保持上一次的芽形态，不闪回、不报错 | 宠物窗口无 DevTools，静默降级优于报错 |
| 次日凌晨（日期翻篇） | 完成率自然归零，芽回到档位 0 | 由 date_key 驱动，无需额外逻辑 |

## 非目标（Non-goals）

- 不做 streak（连续达标天数）驱动的生长。
- 不做身体水位线。
- 不做用户可调档位/阈值。
- 不新增事件常量（parity 护栏），不新增「主提醒」概念。
- 不改动「小满」的基础形象（水滴 + 芽 + 短手的本体不变），只改芽的生长形态表达。
