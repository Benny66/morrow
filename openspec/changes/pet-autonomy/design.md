# design — 小满的自主时间

## 1. 三个关键取舍

### 1.1 微动作是「叠加层」，不是新的 `PetAnim` 值

`PetAnim` 的九个值来自 codexpet 图集的行序（外部约定），它的语义是**状态**：
等待处理 / 庆祝 / 生成中。而"张望""伸懒腰"不是状态，是**状态之上的装饰动作**——
它们可以在 `idle` 期间发生，也可以在半秒后被打断，且不应该影响气泡的优先级判断。

故微动作走独立的 ref + 独立 class（`pet--micro-{kind}`），**不改 `anim`**。
若把 `stretching` 塞进 `PetAnim`，`setAnim` 的 holdTimer、气泡优先级链、
以及"有待处理时不演"的既有条件会全部被牵连。

代价：两套 class 可能同时作用于同一个元素（呼吸 + 伸懒腰都动 `.pet__body`）。
解决：微动作期间给根节点加 `pet--micro-active`，把呼吸动画 `animation-play-state: paused`
（**不是删掉**——删掉会让呼吸在微动作结束时从头开始，看起来像"卡了一下"）。

### 1.2 调度挂在既有 4 秒轮询上，不新增计时器

`Pet.vue` 现在已有三个计时来源：`PET_SETTINGS_POLL_MS`（4s 轮询）、
自动收起计时器、`holdTimer`。再加一个 `setInterval` 会让"谁在什么时候动"变得难以推理。

做法：在 4 秒轮询的 tick 里递减 `nextMicroActionIn`（每次减 4000ms），归零则触发。
代价是调度精度 ±4 秒——对"40–90 秒一次的张望"完全够用，用户感知不到。
收益是**所有"宠物自己动"的决策都发生在同一个函数里**，排查时只有一处要看。

### 1.3 打盹的信号复用 `PauseState.Reason`，不新增空闲检测

`GetPauseState()` 已经在轮询，`Reason` 的取值里有 `idle`（系统空闲）与 `lock`（锁屏）。
这两者合起来就是"用户不在"的准确定义，且**是既有能力、既有权限、既有单一真相**
（`internal/pause/provider.go`）。另起一套键鼠检测只会制造第二个"用户是否在场"的判定。

规则：`Reason ∈ {idle, lock}` 连续 8 分钟 → 打盹。

注意与**贴边收起**互斥：收起时窗口在屏幕外，打盹没有观众，也不该占 CPU。

## 2. 长期成长：为什么是「累计完成天数」而不是 streak

| 方案 | 单调性 | 需要新持久化 | 判定复杂度 |
|---|---|---|---|
| 用 `Streak`（按提醒项的连续天数） | ✗ 断一天归零 | 需要跨提醒聚合 + 新聚合逻辑 | 中 |
| 用「累计完成天数」`COUNT(DISTINCT date_key)` | ✓ 天然单调 | 不需要 | 低 |
| 用「累计完成次数」 | ✓ | 不需要 | 低，但奖励"次数多"而非"坚持久" |

选累计完成天数：**单调性由查询本身保证**，不需要高水位字段、不需要迁移、
不需要在配置里存一个"历史最好成绩"。断一天不会让芽缩回去——这正是要的。

**口径是全局的，不按场景过滤。** 今日统计必须跟随启用场景（换场景就该换目标），
但形态不能跟着换：用户切到一个新场景，芽不该瞬间缩一级。代价是"累计"包含已删除
场景的记录——这是刻意的，删除场景同样不该抹掉已经长出来的芽。

档位边界（唯一真相在 Go，前端只做"整数 → class"）：

| 累计完成天数 | 档位 |
|---|---|
| 0 | 0 小芽苗 |
| ≥1 | 1 |
| ≥7 | 2 |
| ≥30 | 3 |
| ≥100 | 4 |

阈值是可调的产品参数，集中成一张表，**不要散落在 if 里**。

### 2.1 形态取 `max(持久化高水位, 长期档)`——迁移只做一次

若形态**只**取长期档，升级当天所有老用户会看到芽突然缩小（他们的累计天数可能还是 1–2 天，
而今天的完成率是 100%）。故引入一个**只增不减的高水位**：

- 旧版本升级后的首次运行时，高水位 = `max(长期档, 今日档)`，保留旧显示效果；
- 之后高水位只随长期档抬升，今日档不再参与形态；
- 全新安装没有旧显示效果要保留，高水位从 0 开始。

不能每天用 `max(长期档, 今日档)`：累计 1–99 天的用户长期档只有 1–3，
一个 100% 的今天会得到 4 档、次日又掉回 1 档——"一夜之间退步"会原样复现。
高水位持久化在 `config.PetShapeHighWater/PetShapeSeeded`，由 `App.GetPetGrowth` 维护；
`PetShapeSeeded` 的迁移判据是旧 config.json 里**没有这个键**（Load 会显式置 false）。

### 2.2 今日只影响神态

今日完成率改映射为三档神态 class：`pet--today-full` / `pet--today-part` / `pet--today-thin`：
高光透明度与是否轻微下垂。**不碰 `scale`**——一旦今日影响尺寸，就又回到"每天早上缩小一次"。
没有启用目标时（`has_target=false`）保持中性，不显示蔫态。

跨档时播一次"长高"（复用 `jumping` 的 1600ms 保持）作为唯一的一次性回执；
提醒/打盹/菜单优先，不抢它们的画面。

## 3. 帧率：打盹是唯一允许 4fps 的状态

`lib/pet.ts` 里有一条明确的禁令：**不要把 idle 降到 4fps**，因为宠物窗口拿不到键盘焦点，
"失焦"是常态而不是例外。这条禁令的适用范围是**常驻待机**。

打盹不一样：它的动画本身是 4 秒一个起伏的慢循环，4fps 采样完全够，且此时用户按定义不在。
故新增 `PET_SLEEP_FPS = 4`，并写清边界：

- 只在 `dozing` 状态生效；
- 醒来时**立刻**恢复到 12 / 8fps，不允许"渐入"，否则第一眼是卡的；
- 有待处理提醒时不允许进入打盹（哪怕暂停原因为 idle）——提醒优先于表演。

### 3.1 实现补充：`PET_SLEEP_FPS` 只作用于 sprite 模式

落地时才发现一个细节：rAF 循环**只在 sprite 模式运行**，builtin 形象完全由 CSS 动画驱动。
故"降帧"分两条路：

- sprite：`loop()` 里 `dozing ? PET_SLEEP_FPS : …`，让图集循环慢下来；
- builtin：`.pet--dozing .pet__svg { animation-duration: 6.4s }`，把呼吸拉长。

两者在观感上是同一件事（"它睡着了，动作变慢"），但代码里是两处，改一处不会影响另一处
——这条写在这里，避免后来的人以为 `PET_SLEEP_FPS` 没生效。

### 3.2 已知限制：打盹只在智能免打扰开启时发生

`shouldDozeNow()` 的判据是 `PauseState.Reason ∈ {idle, lock}`，而 `Paused` 为真的前提
是智能免打扰开着。用户把自动暂停关掉之后，即使离开一整天，宠物也不会打盹。

**为什么不顺手补**：另一条可选信号是 sit 的空闲态，但那等于把"用户是否在场"的判定
在宠物侧再做一份——违反铁律 1。真要修，正确的位置是让 `pause` 在「用户关掉自动暂停」
时仍然上报 `Reason=idle`（只作为信号，不触发暂停），而不是在 `Pet.vue` 里另判一套。

这条是刻意的取舍，不是遗漏；归档时应保留在规格的「已知限制」里，而不是当成 bug 修掉。

## 4. 为什么行为引擎放在前端

行为是**表现层关注点**：它决定"现在动一下"，不改变任何领域事实。
放 Go 侧会导致每次微动作都过一次 IPC，并让 `app.go` 多出一批 `StartPetIdleLoop()` 之类的绑定，
把一个纯视觉问题变成管道契约问题。

Go 侧本变更只做一件事：把"累计达标天数 → 档位"算好（判定逻辑的唯一真相仍然在 service）。

## 5. 风险

| 风险 | 处置 |
|---|---|
| 微动作在用户专注打字时分散注意力 | 幅度上限 ≤4px、无气泡、无声；暂停/演示/待处理/倒计时一律不演 |
| 打盹与贴边收起状态互相污染 | 收起态直接跳过打盹；打盹不改变窗口位置，也不进 `petDock` 的状态机 |
| 唤醒抖动（pointerenter 与 pause 解除同时触发） | 唤醒走"幂等"函数：已在 idle 就什么都不做；惊醒动画只播一次 |
| 4 秒轮询里塞进动画决策，让轮询变"有权重" | 调度只做整数递减与一次分支判断；不改任何轮询调用 |
| `prefers-reduced-motion` 用户看到"宠物不动了"以为坏了 | 这是既定行为（`pet-character.md` 已声明）；事件反馈（挥手/庆祝/惊醒）仍然保留 |

## 6. 与铁律的对应

- **单一真相**：档位阈值与合成规则只在 `growth.go`；高水位的持久化只在
  `App.GetPetGrowth`；时间常量只在 `lib/pet.ts`，CSS 通过根节点变量消费，不复制数字。
- **禁硬编码色值**：微动作与神态只用 `--color-primary-*` / `--color-success` 的透明度变化。
- **事件契约不变**：不新增 `pet:*` 事件，`parity_test.go` 不受影响。
- **护栏要"感知自己瞎了"**：新增 `internal/guard/pet_behavior_test.go`，两件事：
  1. 解析 `Pet.vue` 的门控表达式，必须命中 pending / pause / presentation / dock /
     reduced-motion / dozing / waking / menu 八个标识；**解析到 0 个即报错**
     （"写法可能已变更，请同步护栏"）。
  2. `lib/pet.ts` 新增的每个微动作常量必须在 `Pet.vue` 里被引用——
     这一条直接针对本轮发现的"图集 5 行了无接线"同型问题：**定义了但没人用，不报错、不崩溃**。
- **分层纪律**：`app.go` 只做高水位的读取/持久化，不碰 gorm；`PetGrowth` 的统计与
  档位合成仍在 service。
