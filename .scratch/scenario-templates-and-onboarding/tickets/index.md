## 执行顺序

```
001（模板目录与个性化纯函数，预重构） ──→ 002（场景页模板库与一键创建） ──┐
                                                                    ├─→ 004（三步向导与个性化实例化） ─→ 005（全量验收与文档收口）
003（引导启动判定、布局与跳过） ─────────────────────────────────────┘
```

- 001 / 003 在开工时处于前沿，可并行；文件不重叠。
- 002 依赖 001；004 依赖 002 + 003；005 依赖 001～004。
- **审计点**：
  - 002 完成后做模板库视觉审计：5 张卡片、展开预览、一键创建、默认停用、无 AI Key。
  - 004 完成后按 spec 7.4 做完整 GUI 验收，再进入 005。
- 001 与 003 不合并：001 是内容与纯逻辑靶心，003 是启动门禁与布局；合并会让纯函数测试被 UI 改动拖慢。
- 003 与 004 不合并：003 交付可独立验证的引导门禁（进入 / 跳过 / 持久化），004 只负责三步业务与实例化。
