# 附件：文件选择 + 粘贴/拖拽图片

**Blocked by**: 005

> 规格：US-29、US-30、US-31

## 目标

快速添加支持系统文件选择、直接粘贴截图与拖拽图片；图片经字节通道发送给 AI，不落盘；截图与文件都能生成一次性/周期草稿。

## 涉及层

- [ ] 数据层
  - 新增内联图片输入类型（名称、MIME、字节）；`GenerateQuickAddDrafts` 接收「文件路径 + 内联图片」。
  - `LoadAttachments` 合并两类来源：去重、最多 8 个附件、图片 5MB/张、文本 200KB 截断、格式表不变。
  - 内联图片只存在内存/请求体，不写临时文件；错误信息能指到具体附件。
- [ ] 逻辑层
  - 文件选择沿用路径读取（图片与文本）；粘贴/拖拽图片走内联字节。
  - 图片作为多模态 content part 发送；文本附件拼入 prompt；混合草稿解析复用 004/005 的 parser。
- [ ] UI 层
  - 快速添加增加「添加图片/文件」入口；支持在输入区粘贴截图、拖拽图片。
  - 附件列表显示类型/文件名/缩略标识，可移除；与文件选择共享 8 个上限。
  - 超限、超大、PDF/未知格式给出可读提示；粘贴/拖拽不要求用户先保存文件。
  - Plan 页 AI 保留现有文件选择；本切片不要求 Plan 页支持粘贴/拖拽（除非共享组件零成本）。
- [ ] 测试
  - Loader：内联图片 + 路径图片/文本；去重；8 条上限；5MB 图片；200KB 文本截断；PDF 拒绝；不产生临时文件。
  - UI：粘贴 PNG → 附件 → 生成草稿；拖拽图片；超限/超大错误；移除附件后重新生成。
  - 有真实 AI Key 时用截图做一次端到端；无 Key 时用 loader/parser 测试 + 手动路径，不伪造验收。
  - `make test`、`make lint` 绿。

## 验收标准

- 粘贴一张日程截图即可进入附件列表，无需先保存为文件；生成草稿时可被模型读取。
- 文件选择仍支持既有图片/文本格式；PDF 明确拒绝并提示复制文字。
- 8 个附件、5MB/图片、200KB 文本上限生效；错误指到具体附件。
- 粘贴/拖拽图片不在磁盘留下临时文件。
- `make test`、`make lint` 通过。
