# 首页聚合与一次性标识

**Blocked by**: 002

> 规格：US-13、US-15、US-16、US-36

## 目标

没有启用场景时，首页「下一条」也能显示最近的一次性提醒；完成一次性提醒不会改变今日完成、目标、连续天数或宠物生长；待处理与强提醒能清楚标出「一次性」。

## 涉及层

- [ ] 数据层
  - `GetTodayStats` 增加「下一条未触发一次性提醒」查询：`once_at > now` 且无 fire 记录；与周期网格、推迟记录取最早者，填充 `NextFireAt` / `NextTitle`。
  - 无启用场景时，不再直接返回空的下一条；仍返回待处理计数与一次性倒计时。
  - 今日完成/目标/连续天数只遍历场景内周期项；一次性项不进入 `Reminders` 进度。
  - `PetGrowth` 复用 `GetTodayStats`，确认一次性完成不改变档位。
- [ ] 逻辑层
  - 一次性完成/跳过/推迟只影响 fire 状态，不写 `CheckIn`；`pending_count` 仍包含 fired 的一次性项。
  - 若一次性项与周期项/推迟记录时间相同，倒计时取最早；标题必须对应当前条目。
- [ ] UI 层
  - 首页「下一条」在无场景 + 有一次性的情况下显示标题与剩余时间。
  - 待处理卡片与强提醒窗口的一次性标识沿用 002 的实现；本切片补齐强提醒/宠物回归验证。
  - 首页「今日完成」不把一次性计入；待处理数包含一次性。
- [ ] 测试
  - 服务：无场景 + 一次性 → `next_fire_at`/`next_title` 正确；有周期 + 更早一次性 → 取更早；一次性完成 → `done_total`/`target_total`/streak/宠物档位不变；`pending_count` 减一。
  - UI：无场景首页倒计时；完成一次性后指标不变；强提醒显示一次性标识；宠物收到 fired 事件。
  - `make test`、`make lint` 绿。

## 验收标准

- 无场景时，10 分钟后的一次性提醒会出现在首页倒计时中，显示正确标题。
- 同时存在周期提醒时，倒计时取更早的那条；推迟记录也参与比较。
- 完成一条一次性提醒后：今日完成数、目标数、连续天数、宠物档位均不变；待处理数减一。
- 强提醒窗口/待处理卡片对一次性项显示「一次性」，不显示空场景名。
- `make test`、`make lint` 通过。
